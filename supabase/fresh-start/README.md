# 코딩쏙 새 DB 전환 전용 SQL

이 폴더는 기존 운영 DB의 오래된 SQL과 분리된 **새 Supabase 전용 기준 구조**입니다.

## 안전 원칙

- 기존 운영 DB와 현재 staging DB에는 자동으로 적용하지 않습니다.
- 실제 학생·학부모·관리자 정보나 고정 비밀번호를 SQL에 넣지 않습니다.
- 각 단계는 빈 시험 DB에서 검증한 뒤 순서대로 적용합니다.
- 기존 `supabase/migrations` 및 `supabase/*.sql` 파일은 수정하지 않습니다.
- 운영 전환 전까지 Vercel 환경변수와 운영 도메인은 변경하지 않습니다.

## 1단계: 계정과 연결 관계

`001_identity_access.sql`은 다음 항목만 만듭니다.

1. 로그인 계정의 역할과 상태를 보관하는 `profiles`
2. 학원 학생 명부인 `students`
3. 학부모 계정과 자녀를 연결하는 `parent_student_links`
4. 선생님 계정과 담당 학생을 연결하는 `teacher_student_assignments`
5. 학생 로그인 번호와 학부모 인증번호를 원문이 아닌 해시로 보관하는 비공개 저장소
6. 학생 본인·연결된 학부모·담당 선생님·관리자를 구분하는 RLS 권한

학부모가 별도 계정을 만들지 않는 현재 방식도 지원할 수 있도록, 서버만 호출할 수 있는 인증번호 확인 함수를 함께 둡니다. 인증번호 원문은 DB 표에 저장하지 않습니다.

## 이후 연결 작업

이 SQL은 안전한 DB 뼈대입니다. 학생 로그인·회원가입과 학부모 세션에는 서버 전용 해시 인증 어댑터가 준비되어 있습니다. 관리자 화면의 인증번호 발급·재발급 기능도 같은 방식으로 교체하고 검증하기 전에는 새 DB를 운영 홈페이지에 연결하지 않습니다.

새 인증 경로를 시험할 때는 서버 환경변수 `SUPABASE_ACCESS_CODE_MODE=hashed`를 사용합니다. 이 값은 새 DB가 준비된 시험 환경에서만 설정하며, 현재 운영 환경에는 아직 설정하지 않습니다.

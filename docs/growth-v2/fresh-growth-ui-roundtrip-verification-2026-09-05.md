## 검사 방식

시험 DB가 비어 있는지 확인한 뒤 가짜 관리자 1명, 학생 1명, 학생 로그인용·학부모용 인증번호, 공개/내부용 가짜 텍스트 파일 각 1개만 준비했다. 성장기록은 미리 넣지 않았다.

임시 검사 도구 `C:/dev/codingssok-parent-preview-check/roundtrip.mjs`는 지정된 시험 DB 주소만 허용한다. 비밀키는 파일에 저장하지 않았으며 검사 프로세스에서만 사용했다. 관리자가 화면에서 작성한 성장기록은 서버에서 읽기 전용으로 대조했다. 시험 자료 정리는 이번에 생성한 ID와 저장 경로에 한정했다.

## 실제 화면에서 확인한 결과

1. 가짜 관리자 로그인 후 운영 메뉴의 `Growth 2.0 성장관리`로 이동했다.
2. 배운 내용, 다음 목표, 잘한 점, 보완할 점, 학부모 전달 문구, 내부 메모를 화면에서 직접 작성했다.
3. `저장됨` 표시와 DB의 초안 저장을 대조했다. 2026년 9월 기록이며 작성자가 해당 가짜 관리자였다.
4. 관리 상태를 `완료`로 선택한 뒤에도 공개 버튼을 누르기 전에는 DB 상태가 `draft`, 공개일이 NULL이었다.
5. `이번 달 기록 공개`를 누르면 공개 완료 안내, 공개 완료 1건, 누적 기록 1건이 표시됐다. 같은 기록이 DB에서 `published`로 바뀌고 공개일이 생성됐다.
6. 관리자 로그아웃 후 학생의 이름·4자리 비밀번호로 로그인했다. 메뉴의 성장기록 버튼으로 이동할 수 있었다.
7. 학생 화면에 관리자가 작성한 배운 내용, 잘한 점, 다음 목표, 선생님 이야기가 표시됐다. 내부 메모 검사 문구는 없었다. 새 학생의 레벨은 1로 표시됐다.
8. 학생도 로그아웃한 뒤 학부모 인증번호로 별도 로그인했다. 관리자/학생 로그인 권한이 남아 있는 상태로 학부모 검사를 대신하지 않았다.
9. 학부모 현황판에도 동일한 네 가지 공개 내용이 표시됐다. 내부 메모와 내부용 파일 검사 문구는 보이지 않았다.
10. 학부모에게 공개된 가짜 파일 1개만 목록에 표시됐으며 해당 다운로드 링크를 클릭했다.

## 완료하지 못한 검사

- **파일의 실제 다운로드 완료는 미확인이다.** 링크 클릭 후 화면 오류는 관찰하지 못했지만, 이것만으로 파일 저장 성공을 판단하지 않았다.
- Chrome 내부 다운로드 페이지는 자동화 도구의 URL 보안 정책으로 열 수 없었다. 정책을 변경하거나 브라우저 내부 자료를 추출하지 않았다.
- 이번에 만든 정확한 가짜 파일 이름만 일반 다운로드 폴더와 Windows 지정 다운로드 폴더에서 확인했으나 찾지 못했다. 다른 저장 위치 여부나 브라우저의 저장 대기 여부는 확인하지 못했다. 홈페이지 오류로 확정하지 않는다.
- 따라서 이번 결과는 성장기록의 화면 왕복 연결 통과이며, 파일 다운로드와 전체 사이트의 모든 기능까지 통과했다는 뜻은 아니다.

# 학생 로그아웃 실패 처리 — 로컬 진단

검사일: 2026-09-06 (한국 시간)

## 결론

**로그아웃 실패를 정상 완료처럼 처리하는 기존 문제를 로컬에서 재현했다. 아직 수정하지 않았다.** 학생 화면의 이름과 역할 표시는 없어지고 `/login`으로 이동하지만, 인증 서버가 500 또는 503 오류를 반환하면 실제 인증 쿠키와 SDK 세션에는 학생 정보가 남는다.

이는 공용 컴퓨터에서 학생 → 학부모로 전환할 때 확인해야 하는 위험이다. 다만 9월 5일 화면 검사 당시의 로그아웃 응답은 확보하지 않았으므로, 당시 학생 인증 경로가 사용된 직접 원인이 500/503이었다고 단정하지 않는다.

## 다음 단계로 이 항목을 선택한 이유

- 가짜 파일의 직접 다운로드 및 시험 자료 정리는 [정리 완료 기록](fresh-manual-fixture-cleanup-2026-09-06.md)에서 끝났다. 이번에는 해당 자료를 다시 만들거나 정리하지 않았다.
- [화면 왕복 검사](fresh-growth-ui-roundtrip-verification-2026-09-05.md)의 8번 항목에 학생 로그아웃 뒤에도 파일 요청에서 학생 인증 경로가 사용된 정황이 남아 있었다.
- [다운로드 수정 검사](fresh-file-download-fix-2026-09-05.md)는 학부모 단독 권한을 별도로 검증했지만, 학생 로그아웃 문제 자체를 고친 것은 아니라고 명시했다.

## 코드에서 확인한 내용

검사 기준 커밋은 `17d6539`, 브랜치는 `codex/fresh-auth-foundation`이다.

1. `src/contexts/AuthContext.tsx`의 `signOut`은 먼저 React 사용자 상태와 `codingssok_user`, `codingssok_role`, 일부 localStorage 키를 지운다.
2. 이후 실제 `auth.signOut({ scope: 'local' })`도 호출한다. 따라서 “로그아웃 호출이 없다”가 원인은 아니다.
3. 그러나 반환값의 `error`를 검사하지 않고, 예외도 무시하며, `finally`에서 항상 `/login`으로 이동한다.
4. 이 프로젝트의 브라우저 인증 클라이언트는 `@supabase/ssr`의 쿠키 저장 방식을 사용한다. localStorage 삭제만으로 해당 인증 쿠키가 삭제되지는 않는다.
5. 설치된 `@supabase/auth-js` 2.110.0의 `_signOut`은 500/503 같은 실패 시 오류를 반환하고 세션 삭제로 넘어가지 않는다. 401/403/404 등 별도로 무시하는 오류와 구분된다.
6. 파일 API `src/app/api/student/files/[fileId]/route.ts`는 유효한 Supabase 사용자가 있으면 그 권한을 먼저 검사하고, 이후 학부모 전용 쿠키 경로를 검사한다. 남은 학생 세션이 있다면 학부모 화면에서도 학생 인증 경로를 사용할 수 있는 코드 구조다. 이것만으로 다른 학생 자료가 유출됐다는 뜻은 아니다.

## 재현 방식과 결과

진단 파일: `src/__tests__/growth-v2/student-logout-diagnosis.test.tsx`.

- 실제 `AuthProvider`와 설치된 Supabase 브라우저 SDK를 실행했다.
- 가짜 학생, 가짜 쿠키, `.example.test` 주소만 사용했다. HTTP 응답은 전부 메모리의 대체 함수가 만들며 외부 통신은 차단했다.
- 정상 204 응답: 학생 표시 제거, 로그인 화면 이동, 인증 쿠키 삭제, SDK 세션 없음.
- 가짜 500 응답: 학생 표시 제거, 로그인 화면 이동, SDK 오류 반환, 인증 쿠키와 학생 세션 남음.
- 가짜 503 응답: 학생 표시 제거, 로그인 화면 이동, SDK 오류 반환, 인증 쿠키와 학생 세션 남음.

**이 3건의 통과는 현재 문제를 재현했다는 뜻이며 보안 검수 통과나 수정 완료가 아니다.** 테스트에 진단용임을 명시했다. 수정할 때 실패 조건에서도 안전하게 처리되는지 검증하도록 기대 결과를 변경해야 한다.

## 다음 한 단계

학생 로그아웃 실패 처리를 수정한다. 최소 범위는 학생 인증 상태 관리와 관련 테스트다. 로그아웃 결과 확인 전에는 성공으로 처리하지 않고, 실패하면 쉬운 안내와 재시도를 제공하며, 정상 종료 시 인증 세션 제거를 확인해야 한다. 실패 중 화면·기존 세션을 어떻게 안전하게 제한할지도 함께 검증한다. 무관한 저장소 키를 광범위하게 삭제하거나 서버 권한을 완화하는 방식은 사용하지 않는다.

그 수정과 로컬 검사가 끝나기 전에는 시험 배포를 새로 하지 않는다. 실제 브라우저에서의 계정 전환 확인은 별도 시험 단계로 남는다.

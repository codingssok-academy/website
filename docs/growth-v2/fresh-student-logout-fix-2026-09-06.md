# 학생 로그아웃 실패 처리 수정

검사일: 2026-09-06 (한국 시간)

## 완료 범위

사용자의 “다음단계 진행” 요청에 따라, [직전 진단](fresh-student-logout-diagnosis-2026-09-06.md)에서 재현한 학생 로그아웃 실패 처리만 수정했다. **로컬 구현·검사·빌드 완료이며 온라인 반영 완료가 아니다.**

- 로그아웃을 요청하면 학습 화면을 숨기고 확인 중 안내를 표시한다.
- SDK 로그아웃 결과의 오류를 검사한 뒤, 로컬 인증 세션이 비어 있는지 다시 확인한다.
- 두 단계가 성공했을 때만 학생 표시용 저장값을 지우고 로그인 화면으로 이동한다.
- 실패하면 로그인 화면으로 이동하지 않고, “로그아웃을 완료하지 못했어요”와 “로그아웃 다시 시도” 버튼을 표시한다. 원본 SDK 오류나 계정 정보를 화면에 출력하지 않는다.
- 요청 중 중복 클릭을 막고, 자동 재시도는 하지 않는다. 사용자가 버튼을 누르면 재시도한다.
- 뒤늦게 끝나는 초기 학습 정보 조회가 로그아웃 후 학생 표시용 저장값을 되살리지 않도록 막았다.
- `sb-`나 `supabase`가 포함된 저장값을 광범위하게 지우던 처리를 제거했다. 인증 쿠키 삭제는 SDK에 맡기며, 앱에서는 정확한 `codingssok_user`와 `codingssok_role`만 정리한다.

## 변경 파일

- `src/contexts/AuthContext.tsx`: 기존 학생 로그아웃 버튼이 연결된 처리 지점. 공용 파일이지만 이 연결을 고쳐야 실제 학생 메뉴에 적용되므로 최소 범위로 수정했다. 관리자·학부모 로그인 API는 수정하지 않았다.
- `src/components/growth-v2/StudentLogoutStatus.tsx`: Growth 전용 확인/오류 안내 화면. 모바일 폭을 고려한 카드, 재시도 버튼, 상태 변경 시 제목 포커스와 접근성 안내를 포함한다.
- `src/__tests__/growth-v2/student-logout.test.tsx`: 기존 진단 파일을 대체하는 회귀 검사. 이제 500/503에서도 정상 완료처럼 이동하는 예전 동작은 검사에 실패한다.
- 직전 진단 문서에는 이 후속 결과의 링크만 추가해 당시 기록을 보존했다.

## 로컬 가짜 검사

실제 `AuthProvider`와 설치된 Supabase 브라우저 SDK를 사용하되, 쿠키·학생·키는 가짜이며 HTTP 응답은 메모리 함수가 제공한다. 네트워크 대체 함수 밖의 fetch 호출은 차단한다. 실제 DB나 사용자 브라우저 프로필은 사용하지 않았다.

전용 검사 **15건**:

1. 정상 204 및 SDK가 세션을 정리하는 401/403/404에서 쿠키·세션 제거 후 이동: 4건.
2. 500/503 오류에서 학습 화면 차단·안내·수동 재시도 성공: 2건.
3. 응답 대기 중 학습 화면 숨김·중복 클릭 방지: 1건.
4. SDK 예외에서 쉬운 안내와 재시도, 내부 오류 내용 비표시: 1건.
5. 후속 확인에서 남은 세션·오류 반환·예외가 있으면 이동 차단: 3건.
6. 초기 XP 조회가 로그아웃 후 끝나도 학생 저장값을 되살리지 않음: 1건.
7. 브라우저 저장값 삭제가 실패하면 성공 처리하지 않고 재시도: 1건.
8. 온라인 인증 설정이 없으면 성공으로 간주하지 않음: 1건.
9. DB 없이 사용하는 기존 로컬 시안 로그아웃 유지: 1건.

관련 없는 저장 키와 가짜 학습 초안이 유지되는지도 함께 검사했다. 안내 화면에서 재시도 버튼과 제목 포커스를 검사했지만, 실제 Chrome/iPhone 화면을 육안으로 검사한 결과와는 구분한다.

## 최종 검사 결과

- 추적 중인 기존 테스트와 새 회귀 검사: **109개 파일 통과, 642건 통과, 기존 1건 건너뜀**. 관련 없는 미추적 실험 테스트는 실행 대상에서 제외했다.
- TypeScript `--noEmit --incremental false`: 통과.
- 수정 소스·새 컴포넌트·회귀 검사 3개 파일 ESLint: 통과. 프로젝트 전체의 무관한 lint 오류를 해소했다고 주장하지 않는다.
- `git diff --check`: 통과.
- 설치된 Next.js 16.2.10의 기본 `next build`: 통과, 정적 페이지 54개 생성.

빌드에는 가짜 공개키와 `http://127.0.0.1:9`만 전달했다. 별도 실행 프로세스에서 서비스 연결용 환경값을 제거하고, 임시 `C:/dev/codingssok-parent-preview-check/offline-logout-build.cjs`로 외부 HTTP/fetch 및 외부 TCP 연결을 차단했다. 실제 환경변수 파일이나 온라인 설정을 편집하지 않았다. 이 빌드 결과물은 배포용 환경값을 담은 결과물이 아니므로 그대로 배포하지 않는다.

검사 도중에는 다음을 바로잡았다:

- SDK 내부 realtime 처리도 `getSession`을 호출하므로, 오류 주입이 앱의 후속 검증 호출에만 적용되도록 테스트를 분리했다. 테스트 SDK도 종료 시 정리했다.
- 테스트 API의 지원하지 않는 `exact` 옵션과 오류 생성자의 인자를 수정했다.
- 최초 전체 병렬 실행에서 기존 `sanitize.test.ts` 초기화가 10초 제한을 넘겼다. 해당 소스나 제한값은 변경하지 않고 `--maxWorkers=2`로 전체 재실행하여 통과했다. 로그아웃 오류 수정 때문에 해당 소스가 바뀐 것은 아니다.

## 안전 경계와 남은 확인

- 운영 DB와 시험 DB 모두 연결하지 않았으며 계정·파일·개인정보를 생성하거나 삭제하지 않았다.
- migration, RLS, 키, 온라인 환경변수, 관리자·학부모 API를 변경하지 않았다. 새 외부 패키지도 설치하지 않았다.
- 원격 push·PR 생성·Preview 또는 운영 배포를 하지 않았다. 소스와 검사 기록만 하나의 로컬 Git 커밋으로 보관한다.
- 실패 안내는 현재 학습 화면의 오동작을 막는 장치다. 서버 장애 중에 인증 세션이 강제로 폐기됐다거나, 주소 직접 이동·다른 탭·새로고침까지 서버 권한이 잠겼다는 뜻은 아니다. 완료 전 기기를 다른 사람에게 넘기지 말라는 안내를 제공한다.
- 9월 5일 실제 로그아웃 응답은 확보하지 않았으므로 당시 현상의 원인을 500/503으로 확정하지 않는다.

다음 별도 단계는 이 수정본의 Preview 반영 및 가짜 계정으로 학생 로그아웃 → 학부모 단독 접속을 실제 브라우저에서 확인하는 것이다. 명시적 push·배포 요청 전에는 실행하지 않는다. 다른 기능으로 자동 진행하지 않는다.

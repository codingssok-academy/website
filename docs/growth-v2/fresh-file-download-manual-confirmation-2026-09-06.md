# 학부모 파일 직접 다운로드 확인 및 시험 자료 정리 상태

기록일: 2026-09-06 (한국 시간)

## 결론

사용자가 시험 파일을 다운로드했고 아래 시험용 본문이 들어 있음을 직접 보고했다. 본문의 실행 고유번호가 준비한 가짜 시험 자료와 정확히 일치한다. 따라서 이번 한 건은 **사용자 직접 다운로드·내용 확인 성공**으로 기록한다.

```text
Fake UI roundtrip verification only. Run: 50a27b78-29d4-4479-ad16-1d36c2e467ee
```

다만 이번 후속 실행의 **가짜 계정·자료 정리는 아직 완료되지 않았다.** 이전 문서의 자료 0건 확인은 이전에 종료한 별도 실행에 대한 것이며, 현재 남겨둔 수동 확인용 자료까지 정리됐다는 뜻이 아니다.

## 확인한 범위와 한계

- 대상은 `codingssok-website`의 기존 Preview 배포이며 코드 기준은 `3a46931698ca597fe1247b1db52e909af4ea318d`다.
- [시험 학부모 화면](https://codingssok-website-iiao2cxur-director-6826s-projects.vercel.app/parent/dashboard).
- 파일은 실제 학생 작품이 아닌 `가짜연결작품.txt` 시험용 텍스트다. 준비한 본문 크기는 78바이트다.
- 사용자가 다운로드 및 내용 확인을 보고했다. 이 후속 단계에서 에이전트가 사용자 디스크의 파일을 다시 읽어 검증한 것은 아니다.
- 저장 위치 변경 보고 뒤 성공 보고가 있었지만, 이것만으로 이전 실패의 원인이 저장 위치였다고 단정하지 않는다.
- `chrome://downloads`의 `ERR_INVALID_URL`은 다운로드 목록 주소를 열지 못한 화면이며, 홈페이지 파일 API 오류의 증거로 사용하지 않는다.
- 앞선 원격 도구의 `ERR_BLOCKED_BY_CLIENT`와 이번 사용자 직접 확인 결과는 구분한다. 차단된 파일을 다른 도구로 자동 재요청하거나 보안 설정을 우회하지 않았다.
- 모든 브라우저, 아이폰, 실제 학생 계정의 모든 파일을 검증한 것으로 확대하지 않는다.

정리 허용 대상은 `codingssok-growth-v2-fresh-test` (`opcdcuedhwyuyhzaubpu`)의 아래 **동일 실행**에 속한 가짜 자료뿐이다.

- 실행 식별자: `50a27b78-29d4-4479-ad16-1d36c2e467ee`.
- 가짜 학생 ID: `ff607de5-75e2-4156-a1f7-8e5971ddb5b0`.
- 가짜 학생 이름: `가짜연결학생`.
- 가짜 관리자 이름: `가짜연결관리자`.
- 준비 이력: Auth 계정 2개, 학생 행 1개, 공개/선생님 전용 파일 2개. 이 수량은 준비 이력이며, 이번 단계에서 DB를 재조회한 수량은 아니다.
- 공개 파일 ID: `7f637ae6-9654-45c5-bb16-58b136714939`.
- 공개 저장 경로: `students/ff607de5-75e2-4156-a1f7-8e5971ddb5b0/admin/188cad4c-0a89-463f-8982-c4d9a15b8110.txt`.
- 비공개 파일 이름: `절대노출금지_연결검사.txt`. 삭제 전 같은 학생 ID로 파일 ID와 저장 경로를 다시 조회해야 한다.

실제 개인정보, 다른 실행의 가짜 자료, 다른 Supabase 프로젝트, 사용자 컴퓨터에 받은 파일은 삭제 대상에 포함하지 않는다. 비밀번호, API 키, 인증 쿠키, 전체 서명 다운로드 주소는 이 문서에 기록하지 않는다.

## 이번 정리가 멈춘 지점

1. 생성 도구의 원본과 고정된 실행 ID/학생 ID/공개 파일 ID를 대조했다. 새 시험 계정이나 파일을 만들지 않았다.
2. Supabase 설정 화면에서 정확한 프로젝트 이름과 ref를 확인했다. 기존 Secret key의 복사 동작을 시도했으나 임시 실행 도구와 브라우저 클립보드 모두 사용 가능한 키를 받지 못했다.
3. 정리 도구는 키 접두어 검사에서 중단됐다. **DB 삭제 요청은 실행하지 않았다.** 이후 비밀키를 공개하거나 새로운 키를 만들지 않았다.
4. 기존 Vercel CLI 로그인 파일의 사용 가능 여부만 메모리에서 확인했다. 재사용 가능한 로그인 토큰이 없었으며 Vercel API 요청이나 환경변수 조회·변경은 하지 않았다.
5. 임시 인증 확인값은 정리했다. 자료가 0건이라고 기록하거나 자동 정리가 완료됐다고 표시하지 않는다.

다음에 필요한 것은 해당 fresh-test 프로젝트의 **기존 Secret key 복사 버튼을 사용자가 직접 누르는 것**이다. 키를 채팅에 붙여넣거나 파일에 저장하지 않는다. 키를 전달받으면 삭제 직전에 모든 대상과 부수 자료를 읽기 전용으로 재확인하고, 확인된 ID/경로만 삭제한 뒤 0건 여부를 검사한다. 예상하지 못한 자료가 발견되면 중단한다.

## 로컬 검사 및 변경 범위

- 한글 파일명·학부모 파일 API·학부모 화면 관련 7개 테스트 파일: 59건 통과.
- TypeScript (`tsc --noEmit --incremental false`): 통과.
- 해당 파일 API 소스/테스트 3개 파일 ESLint: 통과.
- 일회성 정리 도구의 Node 문법 검사 통과. 실제 DB 동작 성공을 의미하지 않는다.
- 앱 소스, 기존 migration, DB 구조·권한, 환경변수 설정을 변경하지 않았다. 새 외부 패키지를 설치하지 않았다.
- 문서만 수정했으므로 Next.js 빌드는 다시 수행하지 않는다. 동일 앱 코드의 직전 빌드 통과 기록은 이전 검증 문서에 보관돼 있다.
- 기존 무관한 미추적 파일은 그대로 두고 이 문서와 이전 기록의 후속 안내만 하나의 로컬 Git 커밋으로 보관한다.
- 원격 push, PR 생성, Preview 재배포, 운영 배포는 하지 않는다.

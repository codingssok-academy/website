## 결론

사용자가 시험 파일을 다운로드했고 아래 시험용 본문이 들어 있음을 직접 보고했다. 본문의 실행 고유번호가 준비한 가짜 시험 자료와 정확히 일치한다. 따라서 이번 한 건은 **사용자 직접 다운로드·내용 확인 성공**으로 기록한다.

```text
Fake UI roundtrip verification only. Run: 50a27b78-29d4-4479-ad16-1d36c2e467ee
```

이후 이번 후속 실행의 **가짜 계정·자료 정리도 완료했다.** 인증 오류로 삭제를 보류했던 경과는 아래에 보존한다. 최종 정리에서는 삭제 직전 대상 대조를 통과한 후 정리했고, 확인한 자료의 잔여 수량이 모두 0건이었다. 이전 별도 실행의 결과와 혼동하지 않도록 이번 실행의 최종 결과는 [별도 완료 기록](fresh-manual-fixture-cleanup-2026-09-06.md)에 보관한다.

## 최초 중단과 키 복사 확인

1. 생성 도구의 원본과 고정된 실행 ID/학생 ID/공개 파일 ID를 대조했다. 새 시험 계정이나 파일을 만들지 않았다.
2. Supabase 설정 화면에서 정확한 프로젝트 이름과 ref를 확인했다. 기존 Secret key의 복사 동작을 시도했으나 임시 실행 도구와 브라우저 클립보드 모두 사용 가능한 키를 받지 못했다.
3. 정리 도구는 키 접두어 검사에서 중단됐다. **DB 삭제 요청은 실행하지 않았다.** 이후 비밀키를 공개하거나 새로운 키를 만들지 않았다.
4. 기존 Vercel CLI 로그인 파일의 사용 가능 여부만 메모리에서 확인했다. 재사용 가능한 로그인 토큰이 없었으며 Vercel API 요청이나 환경변수 조회·변경은 하지 않았다.
5. 임시 인증 확인값은 정리했다. 자료가 0건이라고 기록하거나 자동 정리가 완료됐다고 표시하지 않는다.

이후 사용자가 기존 키의 복사를 완료했다고 보고했다. 같은 fresh-test 프로젝트의 기존 키 복사 버튼과 일회성 프로세스를 통해 키 전달을 확인했다. 따라서 **키 복사 미완료는 현재 중단 사유가 아니다.** 키 값은 출력하거나 파일에 저장하지 않았다.

## 후속 읽기 검사 결과 — 정리 보류

1. 고정된 fresh-test 주소만 허용하는 일회성 도구로 삭제 전 자료 수량과 가짜 계정·학생·파일의 동일 실행 여부를 확인했다. 다른 프로젝트로의 요청과 리디렉션은 금지했다.
2. 읽기 검사에서 `PGRST303` 인증 오류를 관찰했다. [Supabase 공식 오류 설명](https://supabase.com/docs/guides/api/rest/postgrest-error-codes)에 따르면 이 코드는 JWT 검증·해석 실패를 뜻한다. 키 복사가 잘못됐거나 특정 테이블 권한이 원인이라고 단정하지 않는다.
3. 사용 중인 SDK가 키를 `apikey`와 `Authorization: Bearer`에 함께 넣는 코드를 확인했다. [새 API 키의 공식 제한 사항](https://supabase.com/docs/guides/getting-started/api-keys)에 따라 일회성 도구에서 **같은 Secret key가 중복된 Bearer 헤더만** 제거하도록 했다. 홈페이지 소스, 프로젝트 키, RLS 또는 DB 권한은 변경하지 않았다.
4. 그 뒤 한 차례 읽기 검사는 인증 단계에서 더 진행됐지만, `user_progress`가 예상 0건과 달리 **2건**이어서 안전 검사로 중단됐다. 초기 가짜 계정 생성 시 생긴 행일 가능성은 있으나 아직 입증되지 않았다.
5. 이 2건이 정확한 가짜 계정 소유이며 경험치 0·레벨 1·풀이 0·코드 실행 0인 경우에만 허용하도록 검증 조건을 추가했다. 그러나 재실행은 `teacher_student_assignments` 수량 조회의 `PGRST303`에서 멈췄다. **진도 2건의 소유자·초깃값 검증은 완료되지 않았다.** 테이블 이름은 실패가 관찰된 위치이며 원인으로 확정하지 않는다.
6. 허용된 자동 수정 3회 이후에도 문제가 남아 도구에 `abort`를 보내 종료했다. 삭제 명령은 전달하지 않았고 계정·학생·파일·진도에 대한 삭제 요청도 실행되지 않았다. 인증 문제가 해결됐다고 결론내리지 않는다.
7. 각 실행에서 클립보드를 비우고, 종료 시 임시 프로세스 환경변수를 제거했다. 새 키 생성·교체·폐기, 프로젝트 설정 변경은 하지 않았다.

**다음 작업은 삭제나 배포가 아니라 인증 오류의 원인을 별도로 확인하는 것이다.** 읽기 검사가 안정적으로 성공하고 진도 2건까지 이번 가짜 실행의 자료로 확인되기 전에는 정리를 재개하지 않는다. 이후에도 확인된 ID/경로만 삭제하고 최종 잔여 수량을 검사해야 한다. 현재 자료가 0건이라고 보고하지 않는다.

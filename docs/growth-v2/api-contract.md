# Growth 2.0 테스트 API 계약

> 이 문서는 “나중에 화면과 서버가 어떤 약속으로 대화할지” 정리한 것입니다. 실제 API 파일은 아직 만들지 않습니다.

## 1. 공통 원칙

- 모든 요청은 별도 Growth 2.0 테스트 프로젝트만 사용
- 로그인 계정은 Supabase Auth 가상 계정
- 요청 본문의 `role`, `student_id`, `teacher_id`만 믿지 않음
- 서버와 RLS가 실제 로그인 사용자와 연결 관계를 확인
- 성공 응답에는 화면에 필요한 최소 정보만 포함
- 실패 로그에는 이름, 연락처, 평가 원문을 남기지 않음
- 로그에는 요청 ID, 내부 사용자 UUID, 오류 코드만 남김
- 변경 요청은 `Idempotency-Key`를 받아 재시도 중복을 차단
- 사용자 안내는 쉬운 한국어, 내부 오류 세부 내용은 서버 로그에만 기록

## 2. 공통 응답 형태

성공 예시:

```json
{
  "data": {},
  "requestId": "가상-요청-식별자"
}
```

실패 예시:

```json
{
  "error": {
    "code": "NOT_ALLOWED",
    "message": "이 학생의 정보를 볼 권한이 없습니다."
  },
  "requestId": "가상-요청-식별자"
}
```

## 3. 학생 API 후보

### `GET /api/growth-v2/student/home`

- 목적: 로그인 학생의 홈 화면 한 번에 조회
- 요청 값: 없음. 학생 ID는 로그인 계정에서 찾음
- 응답 값: 학생 표시 이름, XP 합계, 레벨 계산값, 연속 학습일, 오늘 미션, 공개 평가 요약, 프로젝트 최신값, 최근 배지
- 호출 역할: 학생
- 권한 확인: `auth.uid()`와 `growth_students.user_id` 비교
- 중복 처리: 읽기 요청이므로 해당 없음
- 쉬운 실패 안내: `학생 정보를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요.`
- 로그 보호: 평가 문장과 표시 이름을 로그에 기록하지 않음

### `POST /api/growth-v2/student/missions/{studentMissionId}/complete`

- 목적: 배정된 미션을 한 번만 완료하고 XP·타임라인을 함께 생성
- 요청 값: URL의 학생 미션 ID, `Idempotency-Key`
- 응답 값: 완료 상태, 지급 XP, 새 총 XP, 새 타임라인 항목
- 호출 역할: 학생 본인
- 권한 확인: 배정 행의 학생이 로그인 학생인지 확인
- 중복 처리: 학생·완료키 고유 제약. 같은 요청은 기존 성공 결과 반환
- 쉬운 실패 안내: `이미 완료한 미션입니다.` 또는 `이 미션을 완료할 수 없습니다.`
- 로그 보호: 미션 제목·학생 이름 대신 내부 ID와 오류 코드만 기록

### `GET /api/growth-v2/student/timeline?cursor=...`

- 목적: 성장 타임라인을 최신순으로 조회
- 요청 값: 선택적 페이지 커서
- 응답 값: 이벤트 유형, 표시 문장, 시각, XP
- 호출 역할: 학생
- 권한 확인: 로그인 학생의 이벤트만 RLS로 조회
- 중복 처리: 읽기 요청이므로 해당 없음
- 쉬운 실패 안내: `성장 기록을 불러오지 못했습니다.`
- 로그 보호: 이벤트 상세 문장을 로그에 남기지 않음

## 4. 학부모 API 후보

### `GET /api/growth-v2/parent/students`

- 목적: 로그인 학부모에게 활성 연결된 자녀 목록 조회
- 요청 값: 없음
- 응답 값: 자녀 내부 ID, 표시 이름, 활성 상태
- 호출 역할: 학부모
- 권한 확인: `parent_user_id = auth.uid()`이며 활성·유효 기간인 연결만 조회
- 중복 처리: 해당 없음
- 쉬운 실패 안내: `연결된 자녀 정보를 찾지 못했습니다.`
- 로그 보호: 자녀 이름과 관계 정보 미기록

### `GET /api/growth-v2/parent/students/{studentId}/weekly-report?weekStart=YYYY-MM-DD`

- 목적: 연결 자녀의 공개 주간 리포트 조회
- 요청 값: 자녀 ID, 주 시작일
- 응답 값: 출석·세 진행률, 공개 평가, 개념, 프로젝트, 성장 이벤트, 대화 제안
- 호출 역할: 학부모
- 권한 확인: 활성 학부모-자녀 연결 + `status=published`
- 중복 처리: 해당 없음
- 쉬운 실패 안내: `아직 공개된 주간 리포트가 없습니다.`
- 로그 보호: 평가 원문과 학생 이름을 로그에 남기지 않음

## 5. 선생님 API 후보

### `GET /api/growth-v2/teacher/students`

- 목적: 로그인 선생님의 담당 학생 목록 조회
- 요청 값: 선택적 활성 여부 필터
- 응답 값: 담당 학생 ID, 표시 이름, 최근 평가 주
- 호출 역할: 선생님
- 권한 확인: `teacher_user_id = auth.uid()`인 활성 배정
- 중복 처리: 해당 없음
- 쉬운 실패 안내: `담당 학생 목록을 불러오지 못했습니다.`
- 로그 보호: 목록 전체를 로그에 남기지 않음

### `GET /api/growth-v2/teacher/students/{studentId}/weekly-evaluations/{weekStart}/draft`

- 목적: 해당 주 초안 또는 공개본을 바탕으로 만든 수정 초안 조회
- 요청 값: 학생 ID, 주 시작일
- 응답 값: 이해도, 참여, 과제, 평가 문장, 개념, 지표 스냅샷, 버전
- 호출 역할: 담당 선생님, 관리자
- 권한 확인: DB에서 실제 로그인 선생님의 활성 담당 관계 확인
- 중복 처리: 같은 학생·주 활성 초안은 최대 1개
- 쉬운 실패 안내: `이 학생의 평가를 작성할 권한이 없습니다.`
- 로그 보호: 평가 문장을 로그에 기록하지 않음

### `PUT /api/growth-v2/teacher/students/{studentId}/weekly-evaluations/{weekStart}/draft`

- 목적: 평가 초안 저장
- 요청 값: 이해도, 참여, 과제 상태, 잘한 점, 보완할 점, 다음 목표, 개념 목록, 공개용 지표 스냅샷 후보, 버전
- 응답 값: 초안 ID, 저장 시각, 버전
- 호출 역할: 담당 선생님, 관리자
- 권한 확인: `auth.uid()`와 활성 담당 관계. 요청의 `teacherId`는 무시
- 중복 처리: 학생·주 활성 초안 고유 제약, 낙관적 버전 확인
- 쉬운 실패 안내: `다른 곳에서 평가가 수정되었습니다. 내용을 다시 확인해 주세요.`
- 로그 보호: 본문 전체를 로그에 남기지 않고 필드 존재 여부와 글자 수만 기록

### `POST /api/growth-v2/teacher/weekly-evaluations/{evaluationId}/publish`

- 목적: 검증된 초안을 학생·학부모에게 공개
- 요청 값: 평가 ID, `Idempotency-Key`, 현재 버전
- 응답 값: 공개 평가 ID, 버전, 공개 시각
- 호출 역할: MVP 기본안은 작성 담당 선생님과 관리자
- 권한 확인: 로그인 선생님이 평가 작성자이며 현재 담당인지 또는 관리자인지 확인
- 중복 처리: 이미 공개된 같은 버전은 기존 결과 반환, 학생·주 현재 공개본은 하나만 허용
- 쉬운 실패 안내: `평가 내용을 다시 확인해 주세요.` 또는 `이미 공개된 평가입니다.`
- 로그 보호: 공개 여부·ID·버전만 기록

### `POST /api/growth-v2/teacher/students/{studentId}/projects/{projectId}/updates`

- 목적: 프로젝트 최근 작업, 다음 작업, 진행률 저장
- 요청 값: 프로젝트 ID, 최근 작업, 다음 작업, 0~100 진행률, `Idempotency-Key`
- 응답 값: 업데이트 ID, 저장 시각, 진행률
- 호출 역할: 담당 선생님, 관리자
- 권한 확인: 프로젝트의 학생과 활성 담당 관계를 DB에서 확인
- 중복 처리: 학생·프로젝트·이벤트 키 중복 차단
- 쉬운 실패 안내: `프로젝트 기록을 저장하지 못했습니다.`
- 로그 보호: 작업 문장 원문을 로그에 남기지 않음

## 6. 관리자 API 후보

### `POST /api/growth-v2/admin/relationships/parent-student`

- 목적: 학부모와 자녀 연결 생성·활성 변경
- 요청 값: 학부모 사용자 ID, 학생 ID, 시작·종료일
- 응답 값: 연결 ID와 활성 상태
- 호출 역할: 관리자
- 권한 확인: DB의 실제 관리자 역할
- 중복 처리: 동일 활성 연결 고유 제약
- 쉬운 실패 안내: `이미 연결된 학부모와 학생입니다.`
- 로그 보호: 이름·연락처 대신 내부 ID만 기록

### `POST /api/growth-v2/admin/relationships/teacher-student`

- 목적: 선생님 담당 학생 배정·해제
- 요청 값: 선생님 사용자 ID, 학생 ID, 시작·종료일
- 응답 값: 배정 ID와 활성 상태
- 호출 역할: 관리자
- 권한 확인: DB의 실제 관리자 역할
- 중복 처리: 동일 활성 배정 고유 제약
- 쉬운 실패 안내: `이미 담당 학생으로 배정되어 있습니다.`
- 로그 보호: 내부 ID만 기록

### `GET /api/growth-v2/admin/weekly-evaluations`

- 목적: 초안·공개·보관 평가 관리
- 요청 값: 주, 상태, 학생 내부 ID 필터
- 응답 값: 최소 목록 정보와 버전
- 호출 역할: 관리자
- 권한 확인: DB 관리자 역할
- 중복 처리: 해당 없음
- 쉬운 실패 안내: `평가 목록을 불러오지 못했습니다.`
- 로그 보호: 목록의 평가 원문 제외

### `PUT /api/growth-v2/admin/missions/{missionId}`

- 목적: 미션 문구, XP 보상, 활성 상태 관리
- 요청 값: 미션 항목과 양수 XP
- 응답 값: 미션 ID, 수정 시각
- 호출 역할: 관리자
- 권한 확인: DB 관리자 역할
- 중복 처리: 미션 코드 고유 제약, 버전 확인
- 쉬운 실패 안내: `미션 설정을 저장하지 못했습니다.`
- 로그 보호: 변경 전후 전체 본문 대신 변경 필드명만 기록

XP 레벨 기준을 관리자가 바꿀지는 아직 원장 결정 사항입니다. 결정 전에는 레벨 규칙 관리 API를 만들지 않습니다.

## 7. 안전한 서버 작업 계약

다음 작업은 브라우저가 여러 표를 직접 수정하지 않고 서버가 DB 거래 하나로 처리합니다.

- 미션 완료 + XP 지급 + 활동 이벤트
- 평가 공개 + 이전 공개본 보관
- 배지 지급 + 배지 활동 이벤트

서버 작업 실패 시 일부만 저장하지 않고 전부 취소합니다.

## 8. 개인정보가 로그에 남지 않게 하는 방법

기록 가능:

- `requestId`
- 내부 UUID
- API 이름
- 허용·차단 결과
- 오류 코드
- 처리 시간

기록 금지:

- 학생·학부모·선생님 실명
- 전화번호, 이메일
- 평가 문장 원문
- 프로젝트 작업 문장
- 로그인 토큰과 API 키
- 요청 본문 전체

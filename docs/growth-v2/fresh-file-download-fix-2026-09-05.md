# 한글 파일명 수정과 학부모 단독 다운로드 재검사

검사일: 2026-09-05 (한국 시간)

## 범위와 결론

사용자가 승인한 한글 파일명 처리 수정과 학부모 단독 파일 다운로드 재검사만 수행했다. 한글 이름의 중복 인코딩 오류를 수정했고, 학생/관리자 인증 없이 학부모 쿠키만 사용한 실제 파일 전송은 통과했다. **Chrome에서 사용자 컴퓨터에 저장이 완료됐다는 증거는 아직 확보하지 못했다.** 파일이 보이지 않는 현상이 완전히 해결됐다고 판정하지 않는다.

운영 DB에 연결하지 않았다. 시험 대상은 `codingssok-growth-v2-fresh-test` (`opcdcuedhwyuyhzaubpu`) 하나이며, 수정 앱은 `127.0.0.1:3107`에서 실행했다. 원격 push, Preview/운영 배포, 기존 migration, DB 권한·구조, 온라인 환경변수는 변경하지 않았다.

## 소스 변경

- `src/app/api/student/files/[fileId]/route.ts`: 60초 서명 주소를 먼저 만든 뒤 `URL.searchParams.set`으로 download 이름만 한 번 인코딩한다. 전체 서명 주소를 디코딩하거나 파일 경로·토큰을 임의 변경하지 않는다.
- 미리보기는 기존처럼 download 파라미터 없이 반환한다. 권한 검사와 삭제 처리는 변경하지 않았다.
- `download-names.test.ts`: 설치된 실제 Supabase SDK와 가짜 네트워크 응답으로 한글·영문·공백·퍼센트·특수문자 이름 및 학부모 단독 권한 검사 17건을 추가했다.
- 기존 `route.test.ts`의 교사 권한·학부모 삭제 차단 등 8건은 유지하고, 변경된 서명 방식에 맞는 기대값 두 개만 갱신했다.

## 실제 학부모 단독 검사

별도 HTTP 클라이언트가 가짜 학생의 학부모 인증번호로 로그인했다. 요청에는 학생/관리자 Supabase 쿠키나 Authorization을 넣지 않았으며, 학부모 로그인 응답에서 받은 `codingssok_parent_session`만 사용했다.

1. 실제 학부모 인증번호 로그인 성공.
2. 학부모 쿠키만 존재하고 학생/관리자 인증 정보가 없음.
3. 로그인하지 않은 파일 요청 403 차단.
4. 변조한 학부모 쿠키 요청 403 차단.
5. 유효한 학부모 쿠키라도 선생님 전용 파일 요청 403 차단.
6. 공개 대상인 자녀 파일 요청 307 허용.
7. 이동 주소가 지정한 fresh-test 저장소의 정확한 가짜 파일 경로임.
8. download 값을 한 번 해석하면 원본 이름 `가짜연결작품.txt`와 일치.
9. 실제 저장소 GET 200 및 Content-Disposition의 filename*가 원본 한글 이름과 일치.
10. 수신한 78바이트가 업로드한 가짜 파일 내용과 완전히 일치.

이 검사는 실제 파일 응답 본문을 메모리에서 대조한 결과다. 디스크에 저장된 파일을 열어 확인한 결과와 구분한다. 이전 진단 문서에서 보류한 학부모 단독 서버 권한 검사는 이 결과로 보완됐지만, 이전 학생 로그아웃 문제를 별도 수정한 것은 아니다.

## Chrome 화면 검사와 남은 한계

컴퓨터 사용 스킬의 읽기/클릭 방식으로 Chrome에서 로컬 학부모 로그인을 하고, 가짜 공개 파일이 목록에 보이며 선생님 전용 파일이 보이지 않음을 확인했다. `받기` 링크 클릭 후 파일 API의 307 응답도 확인했다.

그러나 브라우저 검사 도구의 download 완료 대기는 20초 뒤 시간 초과했고, 일반 Downloads 폴더에서 해당 가짜 파일을 확인하지 못했다. 링크는 기존 `target="_blank"` 구조이나, 이것이 미저장의 원인이라고 단정하지 않는다. 브라우저 내부 다운로드 페이지에 대한 기존 접근 제한을 우회하지 않았고, Chrome 보안/다운로드 설정을 변경하지 않았다. 이 한계 때문에 사용자 컴퓨터의 실제 저장 완료는 미확인으로 남긴다.

## 시험 자료 정리

검사 직전 주요 시험 테이블과 Auth 사용자는 0건이었다. 이번 실행에서 생성한 가짜 계정 2개, 가짜 학생 1명, 가짜 파일 2개만 정확한 ID/경로로 정리했다. 실제 학생 개인정보는 사용하지 않았다.

정리 후 `profiles`, `students`, `student_growth_records`, `student_attendance_records`, `announcements`, `student_files`, `user_progress`, `xp_history`, `student_activity_log`, Auth 사용자는 모두 0건으로 확인됐다. 생성한 저장소 객체 두 개도 없어졌음을 확인했다. 다른 데이터는 삭제하지 않았다. 삭제한 것은 재생성 가능한 가짜 시험 자료뿐이다.

로컬 시험 서버를 종료했다. 임시 비밀키는 실행 프로세스의 메모리에만 사용하고 정리했으며, `.env`나 Git 파일에 저장하지 않았다. 이 문서에는 인증키·쿠키·서명 토큰을 보관하지 않는다.

## 검사 자료 생성 오류 보완

검사용 여러 성장기록의 필드 구성이 달라 일부 행에 `strengths`, `next_goal`, `parent_message`가 없었다. 묶음 insert에서 빠진 값이 NULL로 처리되어 필수값 제약 조건에 걸렸다. 모든 행에 동일한 필수 필드와 빈 문자열 기본값을 명시했다. 지난달 공개 기록의 공개일도 분리해 최신 기록 순서가 결정되도록 했다.

기존 검사 준비 과정의 가짜 프로필 승인 상태 보정은 유지했다. 가짜 학습 활동은 지정된 시험 DB의 서버 클라이언트로 준비했다. 홈페이지 코드나 DB의 제약 조건을 완화하지 않았다.

검사용 임시 스크립트: `C:/dev/codingssok-parent-preview-check/check.mjs`. 비밀키는 파일에 저장하지 않았고, 실행 중인 검사 프로세스에서만 사용했다. 사용 후 클립보드와 프로세스 환경변수를 비웠다.

## 실제 Chrome 화면에서 확인한 사항

1. 틀린 학부모 인증번호는 거부되며 안내 문구가 표시됐다.
2. 올바른 인증번호로 가짜 학부모 로그인이 성공했다.
3. 이름이 같은 가짜 학생 두 명 중 인증번호에 연결된 학생의 학교와 학년만 표시됐다.
4. 현재 공개 성장기록의 배운 내용, 잘한 점, 다음 목표, 학부모 안내가 표시됐다.
5. 2026년 9월 출석에 출석/결석/보강 각 1회와 예정 1회가 표시됐다. 다른 달과 동명이인의 출석은 표시되지 않았다.
6. 공개한 가짜 작품 파일 한 개만 목록에 표시됐다.
7. 공개 공지만 표시되고 작성 중/보관 공지는 표시되지 않았다.
8. 해당 학생의 가짜 학습 활동이 표시됐다.
9. 화면 본문에 비공개 및 동명이인 구분용 검사 문구가 없었다.
10. 시험 DB에 저장한 다음 수업 목표를 변경한 뒤, 화면 새로고침으로 변경된 내용이 표시됐다.
11. 학생을 비활성화한 뒤 기존 학부모 로그인으로 새로고침하면 현황판 대신 인증 화면으로 돌아갔다.

이 검사는 서버 API로 준비한 가짜 기록의 표시를 확인한 것이다. 관리자 입력 화면에서 직접 저장하는 전체 왕복 검사를 완료했다는 의미는 아니다.

## 검사 제한

- 독립 HTTP 검사 요청은 Vercel 접근 보호의 401 응답에 막혔다. 해당 응답은 홈페이지 인증 실패가 아니라 `Protected deployment` 응답임을 확인했다.
- Vercel 보호 설정을 변경하거나 우회하지 않고 로그인된 Chrome에서 화면을 검사했다. 보호 응답을 홈페이지 보안 검사 통과로 집계하지 않았다.
- 공개 파일은 목록 표시까지 확인했다. 이번 검사에서 실제 다운로드는 검증하지 않았다.
- 누적 XP 430/460은 검사 데이터였으며, 이번 실제 화면 검사만으로 API의 누적 XP 값을 검증했다고 주장하지 않는다. 관련 계산과 접근 제어는 아래 로컬 자동 검사의 범위다.

## 로컬 검사 및 정리

- 학부모 대시보드/세션 관련 자동 검사: 4개 파일, 30건 통과.
- 임시 검사 스크립트: `node --check` 통과.
- 홈페이지 타입 검사(`tsc --noEmit`)와 학부모 연결 관련 4개 파일의 ESLint 검사 통과.
- 홈페이지 소스는 이번 재검증에서 수정하지 않았다. 기존 무관한 미추적 파일도 변경하지 않았다.
- 검사 후 다음 항목은 모두 **0건**으로 확인했다: Auth 사용자, 프로필, 학생, 성장기록, 출석, 공지, 파일 메타데이터, 학습 진행/XP, XP 이력, 학습 활동.
- 이번 검사에서 업로드한 가짜 파일은 정확한 저장 경로로 삭제하고, 해당 파일이 남아 있지 않은 것도 확인했다.
- 가짜 계정 및 자료는 검사용으로 만든 것이며, 모두 정리했다. 실제 학생 개인정보는 사용하지 않았다.

다음 별도 검사 후보: 관리자 화면에서 직접 저장 → 학생/학부모 표시 확인, 공개 파일 다운로드 확인. 자동으로 다음 기능을 진행하지 않는다.

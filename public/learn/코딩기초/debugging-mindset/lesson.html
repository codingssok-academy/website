"왜 안 될까?" 찾아내는 슈퍼파워 배우기

1
라면, 먹을 수 있을까?
5분

선생님이 라면 끓이는 법을 이렇게 알려줬어. 이 순서대로 하면 맛있는 라면이 될까?

📝 선생님의 라면 레시피
  1. 물을 끓인다
  2. 면을 넣는다
  3. 면을 꺼낸다
  4. 먹는다
❓ 뭐가 빠졌지? 한 번 찾아볼까?

같이 생각해보기 — 위 레시피에는 수프 넣기, 시간 재기, 그릇에 담기가 빠져있어. 이렇게 지시가 이상하거나 빠진 걸 버그(Bug)라고 해!

2
버그? 그게 뭔데?
10분

🐛 "버그"의 역사

옛날에 어떤 컴퓨터가 갑자기 고장 났어. 알고 보니 컴퓨터 안에 진짜 나방(벌레)이 들어가서 부품을 건드렸대! 그 이후로 컴퓨터가 이상하게 동작하는 이유를 "버그(벌레)"라고 부르게 됐어.

🔍 "디버깅"은 뭐야?

De(없애다) + Bug(벌레) = Debug(버그를 없앤다)

즉, "왜 안 될까?"를 찾아서 고치는 일이야. 이건 엄청 중요한 능력이야. 왜냐면…

💡 모든 프로그래머는 하루의 절반을 디버깅에 쓴다!

너희들이 나중에 뭘 만들든 — 게임, 앱, 로봇, AI — 버그는 항상 생겨. 버그를 잘 찾는 사람이 진짜 실력자야.

3
디버깅 탐정 3단계 — LAF 🔎
10분

버그를 찾는 방법은 탐정이 범인 찾는 거랑 똑같아. LAF 3단계만 기억해!

L
LOOK
잘 봐
지금 결과가 뭐야? 뭐가 이상해? 눈으로 자세히 관찰!
A
ASK
물어봐
원래 뭐가 되어야 하지? 왜 지금은 다르지?
F
FIX
고쳐봐
어디가 다른지 한 글자씩 비교해서 고쳐!

예를 들어볼까?

계산기에 1 + 1을 넣었는데 결과가 3이 나왔어.

  • Look: 결과가 3이네
  • Ask: 원래 1+1은 2가 나와야 하는데 왜 3이지?
  • Fix: 계산기가 +를 -로 바꿔놨네! 고치자
4

이제 너희가 탐정이 되어볼 차례야. 아래 이상한 지시들에서 뭐가 빠졌는지 찾아봐!

🔎 문제 1. 학교 가는 길

2. 학교에 도착한다
🔎 문제 2. 손 씻기

2. 비누를 묻힌다
3. 수건으로 닦는다
🔎 문제 3. 자전거 타기
1. 자전거에 올라탄다
2. 페달을 돌린다
3. 원하는 곳에 도착한다
5
컴퓨터 코드 속 버그 찾기 💻
20분

이번엔 진짜 컴퓨터 코드야. 파이썬으로 "고양이"라는 단어를 10번 출력하려고 했어. 그런데…

🐱 버그가 숨어있는 코드

# 고양이를 10번 출력하고 싶다 for i in range(10): print("강아지") ← 🐛 버그 발견!

LAF로 풀어볼까?

  • Look: "강아지"가 10번 나올 거야
  • Ask: 우리가 원한 건 "고양이"인데?
  • Fix: "강아지" → "고양이"로 바꿔!

✨ 고친 코드

for i in range(10): print("고양이") ✅ 버그 수정 완료!

🎯 이번엔 혼자 찾아봐

1부터 5까지 더하고 싶어. 답은 15(1+2+3+4+5)가 나와야 해.

total = 0 for i in range(1, 5): total = total + i print(total) # 결과: 10 (15가 나와야 하는데!)
🔎 어디가 버그일까?
6
AI도 디버깅이 필요해 🤖
15분

AI한테 물어봤는데 이상한 답이 나올 때가 있어. 이럴 때 어떻게 할까? 내 질문을 디버깅해보는 거야!

😵 나쁜 질문 vs 좋은 질문

🐛 나쁜 질문
"코드 짜줘"
AI가 뭐를, 어떤 언어로, 어떻게 짜야 할지 모름. 이상한 답 나옴.
✨ 좋은 질문
"파이썬으로 1부터 10까지 더하는 코드를 초등학생도 알 수 있게 주석 달아서 짜줘"
언어, 목적, 대상이 명확해서 정확한 답 받음.
🐛 나쁜 질문
"이거 왜 안 돼?"
AI는 "이거"가 뭔지 몰라! 코드도 에러도 안 보여줬음.
✨ 좋은 질문
"[내 코드 붙여넣기] 이 코드 돌렸더니 '인덱스 에러'라고 나왔어. 왜 그래?"
코드와 정확한 에러 메시지를 주니까 AI가 바로 원인 파악.
🎯 AI에게 물을 때 기억할 3가지:
① 뭘 하고 싶은지 ② 무슨 언어인지 ③ 문제 상황이 뭔지

중요한 사실! AI 답이 항상 맞는 건 아니야. 항상 직접 실행해서 확인하는 습관을 들이자!

오늘의 정리 📝

🎉 오늘 배운 슈퍼파워

  1. 버그는 "컴퓨터가 이상하게 동작하는 이유"
  2. 디버깅은 그걸 찾아서 고치는 일 (엔지니어의 50% 일!)
  3. LAF 3단계: Look → Ask → Fix
  4. 코드, 일상, AI 질문… 전부 디버깅할 수 있음
  5. AI 답은 항상 검증하기! (실행해봐, 정말 맞나?)
💪 "왜 안 될까?"를 잘 찾는 사람이 진짜 코딩쏙 학생이야!

🏠 이번 주 탐정 미션

집에서 다음 주까지 해올 숙제야. 공책에 적어서 다음 수업에 가져오기!

  1. 일상 버그 3개 찾기 — 우리 집/학교에서 "이상하게 돌아가는 것" 3개를 찾고, LAF로 원인 분석하기 (예: 엄마가 시킨 심부름에 뭐가 빠졌나?)
  2. AI에게 좋은 질문 3개 만들기 — 나바쌤에게 질문할 "좋은 질문" 3개를 미리 만들어오기 (① 뭘 원해 ② 어떤 언어 ③ 어떤 상황)
  3. 보너스 — 나쁜 질문을 일부러 해보고, AI 답이 이상한지 확인하기. 왜 이상한지 공책에 적기!

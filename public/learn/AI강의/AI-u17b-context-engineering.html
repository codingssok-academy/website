1. 프롬프트 엔지니어링 → 컨텍스트 엔지니어링

앞 단원(u05~u09)에서 프롬프트 엔지니어링을 배웠어요. "AI에게 질문을 잘 하는 법"이죠. 그런데 요즘 AI 개발자들은 "프롬프트만으로 한계"라는 걸 알았어요.

💡 Andrej Karpathy(OpenAI 공동창업자)가 말했어요: "LLM의 성능 차이는 프롬프트 기술보다 컨텍스트 엔지니어링에서 나온다."

프롬프트 vs 컨텍스트

프롬프트 엔지니어링컨텍스트 엔지니어링
질문 문장을 잘 쓰는 기술AI가 일하는 환경 전체를 설계
한 번의 대화지속되는 세션 + 기억 + 도구
"어떻게 물을까""AI에게 무엇을 주고, 무엇을 감출까"
예: "요약해줘, 3줄로"예: "이 문서 + 회사 규칙 + 이전 답변 + 계산기 도구를 줬다"

2. 컨텍스트를 구성하는 5가지 요소

① 시스템 프롬프트 (System Prompt)

AI의 정체성과 행동 규칙. 사용자가 바꿀 수 없어요.

당신은 친절한 수학 선생님입니다.
- 초등학생 수준의 설명을 사용합니다
- 답을 바로 주지 말고 힌트부터 제공합니다
- 욕설/폭력적 질문은 정중히 거절합니다

② 사용자 메시지 (User Message)

학생/사용자가 실시간으로 보내는 질문. 매번 바뀌어요.

③ 문서 / RAG (Retrieval Augmented Generation)

AI에게 참고 자료를 먼저 읽힌 뒤 답하게 하는 방식. 환각을 크게 줄여요.

다음 교과서 내용을 참고해서 답해:
[교과서 3페이지 전문 삽입]

질문: 광합성이 뭐야?

④ 도구 (Tools / Function Calling)

AI가 직접 계산기, 웹검색, 파일 읽기 같은 외부 기능을 호출할 수 있게 해요. MCP가 여기에 속해요.

사용 가능한 도구:
- calculator(expression)
- search_web(query)
- read_file(path)

질문: 지금 서울 기온이 몇 도야?
→ AI가 search_web("서울 기온") 호출

⑤ 메모리 (Memory)

이전 대화의 중요한 정보를 요약해서 다음 세션에 넘기는 것. 예: "이 학생은 고1, 수학 약함, 파이썬 공부 중".

3. Harness — AI를 감싸는 환경

Harness(하네스)는 말 그대로 "AI를 안전하게 태우는 마구(馬具)"예요. AI는 고성능 말이고, 사용자는 기수, Harness는 고삐와 안장이에요.

⚠️ 좋은 Harness 없이 AI만 강하면 말이 길을 벗어나요. 나쁜 답, 환각, 위험한 행동이 나와요.

Harness의 역할

  • 안전 필터: 폭력/성/개인정보 질문 차단
  • 출력 검증: AI가 내놓은 답이 JSON 형식 맞는지 검사
  • Rate Limiting: 한 학생이 분당 100번 질문 못 하게 제한
  • 로깅: 무엇을 물었고 어떻게 답했는지 기록 (감사용)
  • Fallback: AI가 고장났을 때 대체 응답 준비
  • 비용 통제: 토큰 사용량 제한

코딩쏙 AI Tutor의 Harness 구조

[학생 질문]
      ↓
[입력 필터] — 욕설 차단, 학습 외 주제 차단
      ↓
[컨텍스트 주입] — 현재 학습 중인 교재 + 학생 레벨
      ↓
[Claude API 호출]
      ↓
[출력 검증] — 답변이 교육적인지, 정답 직접 알려주지 않는지
      ↓
[로깅] — Supabase에 저장
      ↓
[학생에게 전달]

🤔 이 단원의 핵심: "좋은 AI 제품은 좋은 모델 + 좋은 Harness"예요. 모델만 강하면 불안정해요.

4. 좋은 컨텍스트 vs 나쁜 컨텍스트

❌ 나쁜 예시

# 시스템 프롬프트
너는 AI야.

# 사용자 메시지
광합성이 뭐야?

→ 결과: 일반적이고 두루뭉술한 답. AI의 학습 데이터에만 의존.

✅ 좋은 예시 (컨텍스트 엔지니어링)

# 시스템 프롬프트
당신은 초등학교 5학년 과학 튜터입니다.
- 설명은 4~5문장 이내
- 어려운 용어 쓰면 즉시 풀어서 설명
- 예시는 학생이 아는 것(수박, 사과나무 등)에서
- 질문으로 끝내서 호기심 유발

# 참고 문서 (RAG)
[초등 5학년 과학 교과서 "식물의 생활" 단원 전문]

# 도구
- draw_diagram(concept) : 개념도 그리기

# 사용자 메시지
광합성이 뭐야?

→ 결과: 교과서 기반, 학생 눈높이, 예시 포함, 호기심 유발 질문으로 마무리.

5. 실전 예: 코딩쏙 AI Tutor

우리 학원 AI Tutor가 학생마다 다르게 대답하는 이유는, 각 학생의 컨텍스트가 다르기 때문이에요.

학생컨텍스트AI 답변 스타일
초6 민수기초 코스 학습 중"for는 반복하는 거야. 사탕 100개 세는 것처럼..."
중2 영희L2 if-else 학습 중"for문은 조건문과 다르게..."
고1 철수KOI 대회 준비 중"이 문제는 O(n²)→O(n log n) 최적화가 핵심..."

6. 연습 & 정리

다음 중 "컨텍스트 엔지니어링"의 예가 아닌 것은?

1
AI에게 학원 규칙 문서를 먼저 읽힌 뒤 답하게 함
2
AI에게 "친절한 튜터가 되어라" 시스템 프롬프트 설정
3
AI에게 "요약해줘" 한 단어만 보냄
4
AI에게 계산기 함수를 도구로 제공
정답: 3 — 짧은 지시 하나만 보내는 건 프롬프트 엔지니어링(그것도 빈약한). 컨텍스트 엔지니어링은 환경 전체를 설계하는 것.

7. 챕터 4 마무리

이 챕터에서 MCP → 대표 서버 → 에이전트 → 워크플로우 → 컨텍스트 엔지니어링까지 배웠어요. 이제 AI를 "도구로 쓰는" 수준에서 "환경을 설계하는" 수준으로 올라왔어요.

한 줄 요약: 프롬프트는 "질문"이고, 컨텍스트 엔지니어링은 "AI가 사는 집을 짓는 일"이다.

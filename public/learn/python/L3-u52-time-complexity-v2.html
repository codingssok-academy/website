시간 복잡도 맛보기:
빠른 코드란?

같은 결과를 내는 코드라도 속도는 다를 수 있습니다. 왜 어떤 코드는 느리고, 어떤 코드는 빠른지 — 시간 복잡도로 설명합니다.

이 유닛에서 배우는 것

  • 시간 복잡도가 무엇인지, 왜 알고리즘의 속도가 다른지 이해합니다.
  • O(1), O(n), O(n²) 세 가지 대표 복잡도를 구분할 수 있습니다.
  • import time으로 실제 실행 시간을 측정하고 비교합니다.
  • 버블 정렬과 sorted()의 속도 차이를 실험으로 확인합니다.
  • 코드를 선택할 때 왜 알고리즘이 중요한지 느낍니다.

시간 복잡도란 무엇인가?

코드가 실행될 때 걸리는 시간은 컴퓨터마다 다릅니다. 그래서 프로그래머들은 "연산 횟수"로 속도를 표현합니다. 이를 시간 복잡도(Time Complexity)라고 하고, Big-O 표기법으로 나타냅니다.

O(1) — 항상 같은 시간

데이터가 몇 개든 실행 시간이 변하지 않습니다. 리스트에서 인덱스로 값을 꺼내는 것이 대표적입니다.

# O(1) 예시: 인덱스 접근 numbers = [10, 20, 30, 40, 50] # 리스트가 100만 개여도 이 연산은 항상 1번 first = numbers[0] # O(1) last = numbers[-1] # O(1) print(first, last) # 10 50

O(n) — 데이터 크기에 비례

데이터가 n개이면 n번 연산합니다. 리스트를 처음부터 끝까지 훑는 작업이 여기에 해당합니다.

# O(n) 예시: 리스트 합산 numbers = [1, 2, 3, 4, 5] total = 0 for num in numbers: # n번 반복 → O(n) total += num print(total) # 15 # 리스트가 100만 개면 반복도 100만 번

O(n²)과 import time으로 실제 측정하기

O(n²) — 이중 반복문의 함정

반복문 안에 또 반복문이 있으면 연산 횟수가 n × n = n² 번이 됩니다. n이 조금만 커져도 연산이 폭발적으로 늘어납니다.

# O(n^2) 예시: 이중 반복문 numbers = [1, 2, 3, 4, 5] for i in range(len(numbers)): # n번 for j in range(len(numbers)): # 또 n번 → 합계 n×n = n²번 print(numbers[i], numbers[j]) # n=5 → 5×5 = 25번 출력 # n=1000 → 1000×1000 = 1,000,000번!

import time 으로 실제 측정하기

import time 모듈의 time.time()은 현재 시각을 초(float)로 반환합니다. 코드 전후로 시각을 기록하면 실행 시간을 구할 수 있습니다.

import time # O(n) 측정 n = 100_000 numbers = list(range(n)) start = time.time() # 시작 시각 기록 total = 0 for num in numbers: total += num end = time.time() # 끝 시각 기록 print(f"O(n) 합산: {end - start:.4f}초")
O(n) 합산: 0.0052초

버블 정렬 vs sorted() — 속도 실험

가장 유명한 O(n²) 알고리즘인 버블 정렬(Bubble Sort)과 파이썬 내장 sorted()를 직접 비교합니다.

버블 정렬 — O(n²)

인접한 두 원소를 비교해 큰 것을 뒤로 보내는 방식입니다. 이중 반복문이므로 O(n²)입니다.

import time import random def bubble_sort(arr): n = len(arr) for i in range(n): for j in range(0, n - i - 1): if arr[j] > arr[j + 1]: arr[j], arr[j+1] = arr[j+1], arr[j] # 데이터 준비 data = [random.randint(1, 1000) for _ in range(3000)] data_copy = data[:] # sorted()용 복사본 # 버블 정렬 측정 start = time.time() bubble_sort(data) print(f"버블 정렬: {time.time()-start:.4f}초") # sorted() 측정 start = time.time() sorted(data_copy) print(f"sorted(): {time.time()-start:.4f}초")
버블 정렬: 1.8203초 sorted(): 0.0003초

sorted()는 내부적으로 Timsort라는 O(n log n) 알고리즘을 사용합니다. n이 클수록 버블 정렬과의 격차가 더 벌어집니다.

# 무작위 리스트 vs 이미 정렬된 리스트 import random unsorted = [random.randint(1, 1000) for _ in range(1000)] already_sorted = list(range(1000)) # 이미 정렬됨

import time def bubble_sort_optimized(arr): arr = arr[:] # 원본 보호 n = len(arr) for i in range(n): swapped = False for j in range(0, n - i - 1): if arr[j] > arr[j+1]: arr[j], arr[j+1] = arr[j+1], arr[j] swapped = True if not swapped: break return arr

왜 알고리즘이 중요한가?

같은 결과를 내도 코드의 효율은 천차만별입니다. 데이터가 작을 때는 차이를 못 느끼지만, 데이터가 커질수록 그 차이는 실용의 문제가 됩니다.

검색 엔진, SNS 피드, 지도 앱 — 이 모든 서비스는 수억 건의 데이터를 실시간으로 처리합니다. 알고리즘의 효율이 나쁘면 아무리 빠른 서버도 소용없습니다.

핵심 요약

  • 시간 복잡도: 데이터 크기 n이 커질 때 연산 횟수가 어떻게 늘어나는지를 나타냄
  • O(1) 상수 시간 — 데이터 크기와 무관, 인덱스 접근 등
  • O(n) 선형 시간 — n에 비례, 리스트 순회 등
  • O(n²) 이차 시간 — n이 커질수록 급격히 느려짐, 이중 반복문
  • import time: start = time.time() → 코드 → time.time() - start로 실행 시간 측정
  • 버블 정렬(O(n²))은 sorted()(O(n log n))보다 n=3000에서 약 6,000배 느림
  • 알고리즘 선택이 코드 품질을 결정한다 — 결과가 같아도 효율은 다름

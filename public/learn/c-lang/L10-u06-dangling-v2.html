dangling 포인터
use-after-free, double free

해제된 메모리를 가리키는 dangling 포인터, 해제 후 사용(use-after-free), 두 번 해제(double free) 오류를 이해하고 방지합니다.

이 유닛에서 배우는 것

  • dangling 포인터가 무엇인지 설명할 수 있습니다.
  • use-after-free 오류를 인식하고 방지합니다.
  • double free 오류를 이해하고 예방합니다.
  • NULL 대입으로 세 가지 문제를 모두 방지합니다.
  • 스택 변수를 가리키는 dangling 포인터도 인식합니다.

dangling 포인터 — 유령을 가리키는 포인터

dangling 포인터는 이미 해제되었거나 더 이상 유효하지 않은 메모리를 가리키는 포인터입니다. "허공을 가리키는 포인터"라고 생각하면 됩니다.

// dangling 포인터 예시 int *p = (int*)malloc(sizeof(int)); *p = 42; free(p); // 메모리 반납 // p는 아직 옛 주소를 기억함 — dangling 포인터! *p = 99; // use-after-free! 위험한 코드 printf("%d\n", *p); // 결과 예측 불가 // 해결: free 직후 NULL 대입 free(p); p = NULL; // dangling 포인터 방지

use-after-free와 double free

// double free 예시와 방지 int *p = (int*)malloc(40); free(p); free(p); // double free! → 오류 // 방지: free 후 NULL 대입 free(p); p = NULL; free(p); // free(NULL) → 아무 일도 안 함 (안전)

스택 변수 dangling 포인터

함수가 끝난 후 지역 변수의 주소를 사용하는 것도 dangling 포인터입니다.

// 스택 변수 dangling 예시 int* bad() { int x = 10; // 스택 변수 return &x; // 함수 끝나면 x는 사라짐 → dangling! } int main() { int *p = bad(); // p는 사라진 x를 가리킴 printf("%d\n", *p); // 미정의 동작! }
지역 변수의 주소를 반환하지 마세요! 함수가 끝나면 스택 변수는 사라집니다.

연습 문제

1
dangling 포인터 정의
쉬움
dangling 포인터란 무엇인가요?
① NULL을 가리키는 포인터
② 해제되었거나 유효하지 않은 메모리를 가리키는 포인터
③ 초기화 안 된 포인터
④ 다른 포인터를 가리키는 포인터
힌트 / 정답 보기
정답: ② dangling 포인터는 이미 해제된 메모리나 유효하지 않은 주소를 가리키는 포인터입니다.
2
double free 방지
쉬움
double free를 방지하기 위한 가장 간단한 방법은?
힌트 / 정답 보기
free(p) 후 바로 p = NULL 대입. free(NULL)은 아무 일도 하지 않으므로 실수로 두 번 free해도 안전합니다.
3
코드 오류 찾기
보통
다음 코드의 문제점을 설명하세요.
코드int *p = malloc(sizeof(int));
free(p); *p = 100; printf("%d", *p);
힌트 / 정답 보기
use-after-free 오류입니다. free(p) 후에 *p = 100으로 접근하면 해제된 메모리에 쓰는 것입니다. 결과를 예측할 수 없고 프로그램이 오작동할 수 있습니다. 수정: free(p) 전에 값을 사용하거나, free 후 p=NULL 대입.
4
스택 dangling
보통
다음 코드가 위험한 이유는?
코드int* getVal() { int x = 5; return &x; }
힌트 / 정답 보기
x는 스택 변수입니다. 함수 getVal()이 끝나면 x는 스택에서 사라집니다. 반환된 &x를 사용하면 이미 사라진 메모리를 접근합니다 (dangling). 수정: static int x나 동적 할당을 사용하세요.
5
안전한 코드 완성
어려움
다음 코드에서 dangling, double free, use-after-free를 모두 방지하도록 수정하세요.
원본int *p = malloc(40); free(p); free(p); *p = 5;
힌트 / 정답 보기
int *p = (int*)malloc(40); if (p == NULL) return 1; // 사용... free(p); p = NULL; // 모든 문제 방지 // free(p) → free(NULL) → 안전 // *p = 5 전에 if(p != NULL) 체크 가능
핵심 정리

핵심 정리

  • dangling 포인터 — 해제된 메모리를 가리키는 포인터
  • use-after-free — 해제 후 메모리 접근 → 미정의 동작
  • double free — 같은 메모리 두 번 해제 → 힙 손상
  • 방지법 — free 후 즉시 p = NULL 대입
  • 스택 dangling — 지역 변수 주소를 반환하지 말 것

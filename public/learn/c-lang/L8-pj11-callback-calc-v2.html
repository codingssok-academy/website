Operation Selector via Function Pointer
함수 포인터에 저장하면 실행 중에 어느 함수를 호출할지 바꿀 수 있다.
사칙연산 계산기를 구현하여 콜백 패턴의 진수를 체험한다.
난이도 함수 포인터 선언/호출 콜백 패턴 함수 테이블 구현
완성 코드 — 함수 포인터 계산기
fp_calc.c #include <stdio.h>

/* 사칙연산 함수들 */
int add (int a, int b) { return a + b; }
int sub (int a, int b) { return a - b; }
int mul (int a, int b) { return a * b; }
int divq(int a, int b) { return b ? a / b : 0; }

/* 함수 테이블: 연산자 → 함수 매핑 */
typedef int (*OpFunc)(int, int);

int main() {
    int a = 10, b = 3;
    char ops[] = {'+', '-', '*', '/'};
    OpFunc funcs[] = {add, sub, mul, divq};
    char *names[] = {"add", "sub", "mul", "div"};
    
    /* 함수 테이블로 모든 연산 수행 */
    for (int i = 0; i < 4; i++) {
        int result = funcs[i](a, b);
        printf("%s(%d, %d) = %d\n", names[i], a, b, result);
    }
    
    /* 단일 fp 사용 예 */
    OpFunc fp = add;
    printf("\nfp = add: %d\n", fp(a, b));
    fp = mul;
    printf("fp = mul: %d\n", fp(a, b));
    return 0;
}

typedef int (*OpFunc)(int, int); — OpFunc라는 타입 별칭을 만들어 선언을 단순화. OpFunc funcs[4]가 OpFunc 배열. 각 원소가 "int를 반환하는 int,int 함수"의 포인터다.
switch 없는 디스패치 — 함수 테이블 패턴
dispatcher.c /* 연산자 문자로 직접 함수 선택 */
int dispatch(char op, int a, int b) {
    typedef struct {
        char op;
        int (*fn)(int, int);
    } Entry;
    
    Entry table[] = {
        {'+', add}, {'-', sub},
        {'*', mul}, {'/', divq}
    };
    
    for (int i = 0; i < 4; i++)
        if (table[i].op == op)
            return table[i].fn(a, b);
    return -1; // 미지원 연산자
}
도전 과제

도전 과제

1 고차 함수: int apply(int *arr, int n, int (*fn)(int)) — 배열의 각 원소에 fn을 적용한 결과의 합을 반환. 제곱, 제곱근, 절댓값 등을 fn으로 전달.
2 메뉴 시스템: 함수 포인터 배열로 "1.이름 입력 2.날짜 출력 3.종료" 메뉴를 구현하라. 선택한 번호로 해당 함수를 직접 호출.
3 정렬 기준 선택: qsort에 전달할 비교 함수를 바꿔가며 오름차순/내림차순/절댓값 기준 정렬을 구현하라.
연습문제
1 int (*fp)(int, int)를 읽는 방법은?
"fp는 (int, int)를 받아 int를 반환하는 함수의 포인터". 안쪽부터 읽음: *fp (포인터) → (int, int) (매개변수) → int (반환형). *fp를 괄호로 묶지 않으면 int *fp(int, int) = "int*를 반환하는 함수"가 된다.
2 fp = add와 fp = &add의 차이는?
C에서 함수 이름은 자동으로 함수의 주소로 변환된다. fp = add와 fp = &add는 완전히 동일. 마찬가지로 fp(a, b)와 (*fp)(a, b)도 동일하다. C는 이 둘을 모두 허용한다.
3 typedef를 사용하는 이유는?
함수 포인터 선언은 복잡하다. typedef int (*OpFunc)(int, int)로 OpFunc라는 타입을 만들면 OpFunc fp; OpFunc funcs[4];처럼 간결하게 쓸 수 있다. 특히 함수 포인터를 매개변수로 받거나 반환할 때 가독성이 크게 향상된다.
4 함수 포인터 배열 OpFunc funcs[4] = {add, sub, mul, divq}에서 funcs[i](a, b)가 동작하는 원리는?
funcs[i]는 i번째 함수 포인터. funcs[0] = add, funcs[1] = sub... funcs[i](a, b)는 "i번째 포인터가 가리키는 함수를 호출하고 a, b를 전달". switch 없이 인덱스로 함수를 선택할 수 있다.
5 콜백 패턴이란 무엇이고 어디에 쓰이는가?
콜백: 함수를 다른 함수에 전달하여 나중에 호출하는 패턴. C 표준 qsort(arr, n, sizeof(int), compare)에서 compare가 콜백. 이벤트 핸들러, GUI 버튼 클릭, 네트워크 응답 처리 등에 사용. 호출자가 "어떻게 처리할지"를 결정한다.

이번 프로젝트 핵심

  • int (*fp)(int, int) — 함수 포인터 선언 패턴
  • typedef로 타입 별칭 만들면 코드가 훨씬 깔끔해짐
  • 함수 이름 = 함수 주소, fp = add 와 fp = &add 동일
  • 함수 포인터 배열로 스위치 없는 디스패치 테이블 구현
  • 콜백 = 함수를 인수로 전달하여 나중에 호출하는 패턴

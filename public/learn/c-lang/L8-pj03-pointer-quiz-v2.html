퀴즈 1~5: 기본 포인터 추적
아래 코드를 기준으로 퀴즈를 푼다. 각 줄이 실행된 후의 값을 추적하라.
기준 코드 int a = 10, b = 20, c = 30;
int *p = &a; // p는 a를 가리킴
int *q = &b; // q는 b를 가리킴
1
*p의 값은?
① p의 주소 (0x...)
② 10
③ 20
④ 알 수 없음
해설 보기
p = &a이므로 p는 a의 주소를 담고 있다. *p는 "p가 가리키는 곳의 값" = a = 10이다. p 자체는 주소값이지만 *p는 그 주소에 저장된 값이다.
2
*p = 99; 실행 후 a의 값은?
① 10 (변화 없음)
② p가 변경됨
③ 99
④ 에러 발생
해설 보기
*p = 99는 "p가 가리키는 메모리에 99를 저장"한다. p는 &a이므로 a의 값이 99로 바뀐다. 이것이 포인터로 원본을 수정하는 원리다.
3
p = q; 실행 후 *p의 값은?
① a의 값 (10)
② b의 값 (20)
③ q의 주소
④ 정의되지 않음
해설 보기
p = q는 p에 q의 값(b의 주소)을 복사한다. 이제 p도 b를 가리키므로 *p = b = 20이다. p = q는 포인터 변수 자체(주소값)를 복사하는 것이다.
4
아래 코드 실행 후 a, b의 값은?
*p = &a;  *q = &b;
*p = *q;
① a=10, b=20 (변화 없음)
② a=10, b=10
③ a=20, b=20
④ a=20, b=10
해설 보기
*p = *q는 "p가 가리키는 곳(a)에 q가 가리키는 곳(b)의 값을 저장"한다. 즉 a = b = 20이 된다. b는 건드리지 않으므로 b = 20 그대로. swap이 아님에 주의!
5
아래에서 컴파일 오류가 나는 줄은?
const int *cp = &a;  // (A)
*cp = 50;  // (B)
cp = &b;  // (C)
① (A)
② (B)
③ (C)
④ 오류 없음
해설 보기
const int *cp는 "가리키는 값을 못 바꿈"이다. (B) *cp = 50은 const 값을 수정하려 해서 컴파일 오류. (C) cp = &b는 포인터 자체를 다른 주소로 바꾸는 건데, 이건 허용된다.

퀴즈 6~10: 배열 포인터 & 포인터 산술
기준 코드 int arr[] = {10, 20, 30, 40, 50};
int *p = arr; // p = &arr[0]
6
*(p + 2)의 값은?
① 10
② 20
③ 30
④ p+2의 주소
해설 보기
p + 2는 arr[2]의 주소. *(p+2) = arr[2] = 30. int 포인터에 +2는 2×4=8바이트 이동이다. p[2]와 완전히 동일한 표현이다.
7
p++; 실행 후 *p의 값은?
① 20
② 10
③ p가 1 증가 (주소+1)
④ arr[0]+1 = 11
해설 보기
p++은 p 자체를 다음 원소 주소로 이동. int 포인터이므로 +4바이트. 이제 p = &arr[1], *p = arr[1] = 20. 중요: p++ 은 값이 아니라 포인터 주소를 바꾼다!
8
p = arr; p += 3; 후 p - arr의 값은?
① 12 (3×4 바이트)
② 3
③ arr[3]의 값 (40)
④ 0
해설 보기
같은 배열을 가리키는 두 포인터의 차는 바이트가 아니라 원소 개수다. p = arr+3이므로 p - arr = 3. 이 기능으로 배열 안에서 현재 위치를 계산할 수 있다.
9
아래 코드의 출력 결과는?
int **pp;
int x = 42;
int *p = &x;
pp = &p;
printf("%d\n", **pp);
① p의 주소
② x의 주소
③ 42
④ 컴파일 오류
해설 보기
pp = &p → pp는 p의 주소. *pp = p (p의 값, 즉 x의 주소). **pp = *p = x = 42. 이중 역참조 두 번으로 x 값에 도달한다.
10
아래 코드 실행 후 arr 배열의 상태는?
int arr[] = {1, 2, 3};
int *p = arr;
*p++ = 10;
① {10, 10, 3}
② {10, 2, 3}
③ {1, 10, 3}
④ {11, 2, 3}
해설 보기
*p++ = 10은 *p = 10 (arr[0] = 10) 후 p를 다음으로 이동. 후위 ++이므로 대입 먼저, 이동 나중. 결과: arr = {10, 2, 3}, p = &arr[1].
점수 집계 & 약점 분석
자주 틀리는 함정
함정 1: p = q (포인터 대입) vs *p = *q (값 대입) — p = q는 "p도 같은 곳을 가리킴", *p = *q는 "p가 가리키는 곳에 *q 값 저장"
함정 2: p++ 은 포인터가 다음 원소로 이동 (주소+sizeof(type)), *p+1은 값에 1을 더하는 것 — 완전히 다르다!
함정 3: *p++ 의 우선순위 — ++이 *보다 먼저 바인딩되므로 *(p++)와 동일. 값을 읽고 나서 p를 증가시킨다.

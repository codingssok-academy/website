const int *p vs int *const p
값 보호 vs 주소 보호

const 위치에 따라 "값을 못 바꾸는 포인터"와 "주소를 못 바꾸는 포인터"가 달라집니다. 헷갈리는 두 가지를 완전히 구분합니다.

이 유닛에서 배우는 것

  • const int *p: 포인터로 값을 바꿀 수 없음을 이해합니다.
  • int *const p: 포인터 주소를 바꿀 수 없음을 이해합니다.
  • const int *const p: 둘 다 고정됨을 압니다.
  • const 포인터를 사용하는 이유(안전성)를 설명합니다.
  • 함수 매개변수에서 const를 올바르게 사용합니다.

const int *p — 가리키는 값을 보호

const가 * 앞에 있으면 포인터를 통해 값을 변경할 수 없습니다. 포인터 자체(가리키는 대상)는 바꿀 수 있습니다.

int a = 10, b = 20; const int *p = &a; // *p = 99; — 오류! 값 수정 불가 p = &b; // OK — 다른 주소로 변경 가능 printf("%d\n", *p); // 20 // a는 직접 수정 가능 a = 99; printf("%d\n", *p); // 오류 아님 — p가 a 가리키면 99

int *const p — 포인터 주소를 보호

const가 * 뒤에 있으면 포인터가 가리키는 주소를 변경할 수 없습니다. 값은 바꿀 수 있습니다.

int a = 10, b = 20; int *const p = &a; // p는 반드시 초기화! *p = 99; // OK — 값 수정 가능 // p = &b; — 오류! 주소 변경 불가 printf("%d\n", a); // 99

세 가지 const 포인터 비교

int a = 1, b = 2; const int *p1 = &a; // 값 보호 int *const p2 = &a; // 주소 보호 (초기화 필수) const int *const p3 = &a; // 모두 보호 // p1: 값 변경 불가, 주소 변경 가능 // *p1 = 9; — 오류 p1 = &b; // OK // p2: 값 변경 가능, 주소 변경 불가 *p2 = 9; // OK // p2 = &b; — 오류

함수에서 const 사용

함수가 배열이나 변수를 수정하지 않는다면 매개변수에 const를 붙여 의도를 명확히 표현하고 버그를 방지합니다.

// 배열을 읽기만 — const 붙이기 int sum(const int *arr, int n) { int s = 0; for (int i=0; i<n; i++) s += arr[i]; // arr[0] = 0; — 오류! const로 보호 return s; } // 문자열 길이 — const char* int my_strlen(const char *s) { int n = 0; while (*s++) n++; return n; } // 배열 수정 필요 — const 없이 void fill(int *arr, int n, int val) { for (int i=0; i<n; i++) arr[i] = val; }

좋은 습관: 읽기 전용 매개변수에는 항상 const를 붙이세요. 실수로 수정하면 컴파일러가 잡아줍니다!

핵심 정리

핵심 정리

  • const int *p: 가리키는 값 변경 불가, 주소 변경 가능 (값 보호)
  • int *const p: 주소 변경 불가, 값 변경 가능 (주소 고정, 초기화 필수)
  • const int *const p: 값도 주소도 모두 변경 불가
  • 암기: * 오른쪽 const = 그 쪽이 고정
  • 함수 매개변수: 수정 안 하면 const 붙이기

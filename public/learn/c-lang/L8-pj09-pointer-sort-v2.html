Indirect Sort with Pointer Array
원본 배열을 건드리지 않고 정렬된 순서로 출력할 수 있다.
포인터 배열 ptrs[]에 각 원소 주소를 저장하고 ptrs를 정렬 — 원본은 그대로, 포인터 순서만 바뀐다.
난이도 포인터 배열 int *ptrs[] 간접 정렬 원본 보존
완성 코드
indirect_sort.c #include <stdio.h>

#define N 5

int main() {
    int arr[N] = {30, 10, 50, 20, 40};
    int *ptrs[N]; // 포인터 배열 선언
    
    /* 1단계: 포인터 배열 초기화 */
    for (int i = 0; i < N; i++)
        ptrs[i] = &arr[i];
    
    /* 2단계: 버블 정렬 (ptrs 기준, 역참조 비교) */
    for (int i = 0; i < N - 1; i++) {
        for (int j = 0; j < N - 1 - i; j++) {
            if (*ptrs[j] > *ptrs[j+1]) {
                int *tmp = ptrs[j]; // 포인터 교환
                ptrs[j] = ptrs[j+1];
                ptrs[j+1] = tmp;
            }
        }
    }
    
    /* 3단계: 원본 출력 (변하지 않음) */
    printf("원본: ");
    for (int i = 0; i < N; i++) printf("%d ", arr[i]);
    printf("\n정렬: ");
    for (int i = 0; i < N; i++) printf("%d ", *ptrs[i]);
    printf("\n");
    return 0;
}
$ gcc indirect_sort.c -o indirect_sort && ./indirect_sort
원본: 30 10 50 20 40
정렬: 10 20 30 40 50
핵심 차이: 일반 정렬은 arr 원소를 직접 이동(큰 데이터 복사 비용). 포인터 정렬은 포인터(주소, 8바이트)만 이동 — 원소가 구조체처럼 클수록 유리하다.
포인터 배열 선언과 초기화
응용: 문자열 포인터 배열 정렬
str_ptr_sort.c #include <stdio.h>
#include <string.h>

int main() {
    const char *names[] = {"Charlie", "Alice", "Bob"};
    int n = 3;
    
    /* 버블 정렬 (strcmp로 비교) */
    for (int i = 0; i < n-1; i++)
        for (int j = 0; j < n-1-i; j++)
            if (strcmp(names[j], names[j+1]) > 0) {
                const char *tmp = names[j];
                names[j] = names[j+1];
                names[j+1] = tmp;
            }
    
    for (int i = 0; i < n; i++) printf("%s\n", names[i]);
    return 0;
}

도전 과제

도전 과제

1 내림차순: 포인터 배열로 내림차순 정렬하여 출력하라. 비교 조건 하나만 바꾸면 된다.
2 원본 인덱스 추적: 정렬 후 각 원소가 원본에서 몇 번 인덱스였는지 함께 출력하라. (ptrs[i] - arr로 계산)
3 상위 K개만: 배열에서 가장 큰 K개를 정렬된 순으로 출력하는 함수를 작성하라.
연습문제
1 int *ptrs[5]와 int (*ptrs)[5]의 차이는?
int *ptrs[5]: int 포인터 5개짜리 배열 (포인터 배열). ptrs[0], ptrs[1]... 각각이 int *.
int (*ptrs)[5]: 5개짜리 int 배열을 가리키는 포인터 (배열 포인터). 2차원 배열 처리에 사용.
2 포인터 교환 시 int *tmp = ptrs[j];를 쓰는 이유는?
ptrs[j]는 int * 타입이므로 tmp도 int *로 선언. tmp = ptrs[j]는 주소값을 복사. 이후 ptrs[j] = ptrs[j+1], ptrs[j+1] = tmp로 포인터(주소)를 교환. 실제 데이터(arr)는 건드리지 않는다.
3 정렬 후 ptrs[i] - arr로 원본 인덱스를 구할 수 있는 이유는?
ptrs[i]는 arr의 어느 원소를 가리키는 주소. ptrs[i] - arr은 arr[0]부터 몇 번째인지 = 원본 인덱스. 예: ptrs[0] = &arr[1]이면 ptrs[0] - arr = 1.
4 이 기법의 실제 활용 사례는?
데이터베이스 인덱스: 실제 레코드(원본)는 그대로, 인덱스(포인터)만 정렬하여 빠른 조회. 파일 시스템: 파일 메타데이터 포인터 배열 정렬. 큰 구조체 배열 정렬 시 복사 비용 절감. qsort 콜백도 내부적으로 유사한 원리.
5 문자열 배열을 포인터 교환으로 정렬할 때 문자열 내용이 복사되지 않는 이유는?
const char *names[]는 각 원소가 문자열의 시작 주소. 교환 시 포인터(주소, 8바이트)만 이동. "Alice" 자체는 메모리 어딘가에 그대로 있고, names[0]이 가리키는 주소만 변경된다. 문자열이 100바이트든 1000바이트든 교환 비용은 동일하다.

이번 프로젝트 핵심

  • int *ptrs[N] — N개의 int 포인터를 담는 배열
  • ptrs[i] = &arr[i] 로 초기화, *ptrs[i]로 값 접근
  • 정렬 시 포인터(주소)만 교환 — 원본 데이터 불변
  • ptrs[i] - arr 로 정렬 후 원본 인덱스 역추적 가능
  • 큰 데이터 정렬 시 복사 비용 절감 — 실무에서 중요한 최적화

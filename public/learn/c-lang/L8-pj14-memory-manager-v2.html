메모리 풀
시뮬레이션
Simple Memory Pool Simulation
배열로 고정 크기 메모리 풀을 구현한다. malloc/free 없이 직접 할당/해제를 관리하는 원리를 배운다.
포인터, 배열, 플래그의 조합으로 메모리 관리자를 시뮬레이션한다.
난이도 메모리 관리 원리 포인터 + 배열 조합 시스템 프로그래밍 맛보기
완성 코드
mempool.c #include <stdio.h>
#include <string.h>

#define POOL_SIZE 8 // 블록 개수
#define BLOCK_SIZE 16 // 각 블록 크기(바이트)

typedef struct {
    char pool[POOL_SIZE][BLOCK_SIZE];
    int used[POOL_SIZE];
} MemPool;

/* 빈 블록 찾아 할당 */
char *pool_alloc(MemPool *mp) {
    for (int i = 0; i < POOL_SIZE; i++) {
        if (!mp->used[i]) {
            mp->used[i] = 1;
            return mp->pool[i];
        }
    }
    return NULL; // 풀 가득 참
}

/* 블록 해제 */
void pool_free(MemPool *mp, char *ptr) {
    int idx = (int)(ptr - mp->pool[0]) / BLOCK_SIZE;
    if (idx >= 0 && idx < POOL_SIZE) {
        mp->used[idx] = 0;
        memset(mp->pool[idx], 0, BLOCK_SIZE);
    }
}

void pool_status(MemPool *mp) {
    printf("풀 상태: [");
    for (int i = 0; i < POOL_SIZE; i++)
        printf("%c", mp->used[i] ? '#' : '.');
    printf("]\n");
}
초기: 풀 상태: [........]
alloc × 3: 풀 상태: [###.....]
free[1]: 풀 상태: [#.#.....]
alloc: 풀 상태: [###.....] (빈 자리 재사용)
메인 함수 — 풀 사용 시나리오
main() int main() {
    MemPool mp = {0};
    
    char *a = pool_alloc(&mp);
    char *b = pool_alloc(&mp);
    char *c = pool_alloc(&mp);
    
    strcpy(a, "Hello");
    strcpy(b, "World");
    strcpy(c, "Pool");
    
    printf("a=%s, b=%s, c=%s\n", a, b, c);
    pool_status(&mp);
    
    pool_free(&mp, b);
    pool_status(&mp);
    
    char *d = pool_alloc(&mp); // b 자리 재사용
    strcpy(d, "Reuse");
    printf("d=%s (b의 자리 재사용)\n", d);
    pool_status(&mp);
    return 0;
}
인덱스 계산: pool_free에서 (ptr - mp->pool[0]) / BLOCK_SIZE — ptr이 pool[i]의 시작이면 거리 = i × BLOCK_SIZE. BLOCK_SIZE로 나누면 i가 나온다.
도전 과제

도전 과제

1 사용률 통계: pool_stats() 함수를 추가해 현재 사용 중인 블록 수, 여유 블록 수, 사용률(%)을 출력하라.
2 int 풀: BLOCK_SIZE를 sizeof(int)로 하는 정수 풀 MemPoolInt를 구현하라. int *pool_alloc_int(MemPoolInt *mp)로 int를 할당.
3 단편화 시뮬레이션: 할당/해제를 번갈아 반복하여 메모리 단편화([#.#.#.#.])가 생기는 상황을 만들고, 연속 2개 블록이 필요하지만 할당 못 하는 상황을 재현하라.
연습문제
1 pool_alloc이 NULL을 반환하는 경우는?
POOL_SIZE개 블록이 모두 used[i] = 1인 경우, 즉 풀이 가득 찼을 때. 사용 전 NULL 체크 필수. 실제 시스템에서 메모리 부족과 같은 상황이다.
2 pool_free에서 포인터 빼기로 인덱스를 계산하는 원리는?
mp->pool[0]은 배열 시작 주소. ptr = mp->pool[i]이면 ptr - mp->pool[0] = i × BLOCK_SIZE (바이트 거리). BLOCK_SIZE로 나누면 i. 포인터 산술로 역인덱스를 구하는 패턴이다.
3 메모리 풀이 일반 malloc보다 유리한 상황은?
실시간 시스템: malloc은 실행 시간이 불규칙. 풀은 O(n) 탐색으로 일정.
단편화 방지: 고정 크기 블록이므로 단편화 없음.
임베디드: malloc이 없거나 힙이 제한된 환경.
게임/서버: 자주 할당/해제되는 객체 (캐릭터, 패킷 등)에 풀을 미리 만들어 사용.
4 memset(mp->pool[idx], 0, BLOCK_SIZE)를 free 시 호출하는 이유는?
해제된 블록에 이전 데이터가 남아있으면 다음 할당자가 그 데이터를 볼 수 있다 (정보 누출). 0으로 초기화하면 보안상 안전하고, 디버깅 시 초기화 여부도 확인 가능하다. 단, 성능이 중요한 경우는 생략하기도 한다.
5 MemPool mp = {0}; 초기화의 의미는?
구조체의 모든 멤버를 0으로 초기화. pool 배열 = 모두 0, used 배열 = 모두 0 (빈 상태). C에서 {0}은 집합체 초기화의 단축형으로, 첫 원소만 0으로 지정하면 나머지도 자동으로 0이 된다.

이번 프로젝트 핵심

  • 메모리 풀 = 고정 크기 블록 배열 + 사용 여부 플래그
  • alloc: 빈 블록 탐색 후 used[i] = 1, 주소 반환
  • free: (ptr - base) / BLOCK_SIZE로 인덱스 역산, used[i] = 0
  • 풀 방식 장점: 단편화 없음, 일정한 할당 시간
  • 포인터 산술로 배열 인덱스를 역계산할 수 있다

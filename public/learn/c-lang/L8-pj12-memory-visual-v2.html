Memory Address Visualizer
%p 포맷과 sizeof로 변수들의 실제 메모리 주소와 크기를 출력하는 도구를 만든다.
배열의 연속성, 포인터 크기, 변수 간 거리를 실제 숫자로 확인하며 메모리를 눈으로 본다.
난이도 %p 포맷 sizeof 연산자 메모리 레이아웃
완성 코드
memvis.c #include <stdio.h>

int main() {
    char c = 'A';
    int i = 42;
    double d = 3.14;
    int *p = &i;
    int arr[] = {10, 20, 30, 40, 50};
    
    printf("=== 기본 변수 ===\n");
    printf("char c: addr=%p, size=%zu, val=%c\n", (void*)&c, sizeof(c), c);
    printf("int i: addr=%p, size=%zu, val=%d\n", (void*)&i, sizeof(i), i);
    printf("double d: addr=%p, size=%zu, val=%.2f\n", (void*)&d, sizeof(d), d);
    printf("int* p: addr=%p, size=%zu, val=%p\n", (void*)&p, sizeof(p), (void*)p);
    
    printf("\n=== 배열 — 연속성 확인 ===\n");
    for (int k = 0; k < 5; k++) {
        printf("arr[%d]: addr=%p (+%zu bytes) val=%d\n",
               k, (void*)&arr[k],
               (char*)&arr[k] - (char*)arr,
               arr[k]);
    }
    
    printf("\n=== 포인터 사실 ===\n");
    printf("p == &i ? %s\n", (void*)p == (void*)&i ? "yes" : "no");
    printf("arr == &arr[0] ? %s\n",
           (void*)arr == (void*)&arr[0] ? "yes" : "no");
    return 0;
}

메모리 블록 시각화 함수
memvis2.c /* 메모리를 16진수 바이트 덤프로 출력 */
void print_mem(const void *addr, size_t size, const char *label) {
    const unsigned char *p = (const unsigned char *)addr;
    printf("%-8s [%p] ", label, addr);
    for (size_t i = 0; i < size; i++)
        printf("%02x ", p[i]);
    printf("\n");
}

int main() {
    int a = 0x12345678; // 리틀 엔디안 확인
    char s[] = "Hi";
    int arr[] = {1, 2};
    
    print_mem(&a, sizeof(a), "int a");
    print_mem(s, sizeof(s), "str s");
    print_mem(arr, sizeof(arr), "arr");
    return 0;
}
출력 (리틀 엔디안 x86):
int a [0x7fff...] 78 56 34 12
// 0x12345678이 78 56 34 12 역순으로 저장!
str s [0x7fff...] 48 69 00
// H=0x48, i=0x69, \0=0x00
arr [0x7fff...] 01 00 00 00 02 00 00 00
리틀 엔디안: 0x12345678을 메모리에 저장할 때 낮은 바이트(0x78)가 낮은 주소에 먼저 온다. x86/x64 프로세서는 리틀 엔디안 방식을 사용한다. 네트워크 프로그래밍 시 바이트 순서 변환이 필요한 이유다.
도전 과제

도전 과제

1 sizeof 표: char, short, int, long, long long, float, double, pointer의 크기를 표로 출력하는 프로그램을 작성하라.
2 포인터 지도: int a, b, c와 int *p = &b를 선언하고 각 변수와 p의 주소, p의 값(*p)을 출력하여 포인터 관계를 시각화하라.
3 구조체 패딩: L9 예고로, struct {char c; int i;}의 크기가 5가 아닌 8인 이유를 메모리 덤프로 확인하라.
연습문제
1 printf("%p", &i)에서 (void *)&i로 캐스팅하는 이유는?
%p는 void * 타입을 기대한다. int *를 void *로 캐스팅하면 컴파일러 경고를 없앨 수 있다. C 표준에서 %p에는 void *를 전달하도록 규정하고 있다.
2 배열 원소 간격이 sizeof(int) = 4인 이유는?
int 배열은 각 원소가 4바이트. arr[0]이 주소 0x1000이면 arr[1]은 0x1004, arr[2]는 0x1008. 포인터 산술에서 p+1은 항상 다음 원소 주소 = 현재 주소 + sizeof(타입)이다.
3 sizeof 연산자와 strlen 함수의 차이는?
sizeof(arr): 컴파일 타임에 결정되는 배열 전체 바이트 크기. char arr[10]이면 sizeof = 10.
strlen(arr): 실행 중 '\0'까지의 문자 수. "Hello"이면 5. sizeof는 '\0' 포함, strlen은 미포함.
4 int *p의 sizeof(p) = 8인 이유는? (포인터가 가리키는 타입과 관계없이)
64비트 시스템에서 모든 포인터는 8바이트. 메모리 주소를 64비트(8바이트)로 표현하기 때문. char *, int *, double *, void * 모두 크기는 8. 포인터 타입(char *, int *)은 "얼마나 읽을지"를 결정하지, 포인터 자체 크기를 결정하지 않는다.
5 리틀 엔디안에서 0x12345678이 78 56 34 12로 저장되는 원리는?
리틀 엔디안: 낮은 주소에 낮은 바이트(LSB)가 먼저 저장. 0x12345678에서 가장 낮은 바이트 = 0x78. 주소 순서: [낮은주소] 78, 56, 34, 12 [높은주소]. 빅 엔디안(네트워크 표준)은 반대: 12, 34, 56, 78.

이번 프로젝트 핵심

  • %p로 포인터 주소 출력, (void *) 캐스팅 필요
  • sizeof(타입): 해당 타입이 차지하는 바이트 수
  • 배열 원소 간격 = sizeof(원소타입) — 연속 메모리 증명
  • 64비트 시스템의 포인터 크기 = 항상 8바이트
  • 리틀 엔디안: 낮은 바이트가 낮은 주소에 저장

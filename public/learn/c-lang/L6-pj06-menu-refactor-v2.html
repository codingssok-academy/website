이 프로젝트에서 배우는 것

  • 리팩토링이 무엇인지 이해합니다.
  • 코드를 역할별로 나누는 단일 책임 원칙을 배웁니다.
  • showMenu / processMenu / doAction 패턴을 익힙니다.
  • while 루프와 함수 조합으로 메뉴 시스템을 만듭니다.
  • main이 짧고 읽기 쉬운 코드를 작성합니다.
PROJECT 06
메뉴 시스템 리팩토링
단일 책임 원칙 + showMenu/processMenu 패턴

리팩토링이란?

리팩토링(Refactoring)은 코드의 동작은 바꾸지 않으면서 구조를 더 읽기 쉽게 개선하는 작업입니다. 긴 main 함수를 역할별로 나눕니다.

리팩토링 전 (나쁜 예)
int main() { // 메뉴 출력 코드 20줄 printf("1.덧셈\n"); printf("2.뺄셈\n"); ... // 처리 코드 30줄 switch(choice) { ... } // main이 100줄 넘어감 }
리팩토링 후 (좋은 예)
int main() { int choice; do { showMenu(); scanf("%d", &choice); processMenu(choice); } while (choice != 0); return 0; // main은 5~10줄 }
// 메뉴 출력 전담 함수 void showMenu() { printf("=== 간단 계산기 ===\n"); printf("1. 덧셈\n"); printf("2. 뺄셈\n"); printf("3. 곱셈\n"); printf("0. 종료\n"); printf("선택: "); } // 연산 처리 전담 함수 void processMenu(int choice) { int a, b; if (choice >= 1 && choice <= 3) { printf("a b 입력: "); scanf("%d %d", &a, &b); } switch(choice) { case 1: printf("%d+%d=%d\n", a, b, a+b); break; case 2: printf("%d-%d=%d\n", a, b, a-b); break; case 3: printf("%d*%d=%d\n", a, b, a*b); break; case 0: printf("종료합니다.\n"); break; default: printf("잘못된 선택\n"); } }
단일 책임 원칙: 하나의 함수는 하나의 일만 합니다. showMenu는 메뉴 출력만, processMenu는 처리만 담당합니다. 이렇게 하면 나중에 메뉴를 바꾸고 싶을 때 showMenu만 수정하면 됩니다.

메뉴 시스템 — 전체 코드

/* ====== 함수로 분리된 메뉴 시스템 ====== */ #include <stdio.h> void showMenu() { printf("\n=== 간단 계산기 ===\n"); printf("1. 덧셈\n2. 뺄셈\n3. 곱셈\n4. 나눗셈\n0. 종료\n"); printf("선택: "); } void doAdd() { int a,b; scanf("%d%d",&a,&b); printf("결과: %d\n",a+b); } void doSub() { int a,b; scanf("%d%d",&a,&b); printf("결과: %d\n",a-b); } void doMul() { int a,b; scanf("%d%d",&a,&b); printf("결과: %d\n",a*b); } void doDiv() { int a,b; scanf("%d%d",&a,&b); if(b==0) printf("0으로 나눌 수 없습니다!\n"); else printf("결과: %d\n",a/b); } void processMenu(int choice) { printf("두 수 입력: "); switch(choice) { case 1: doAdd(); break; case 2: doSub(); break; case 3: doMul(); break; case 4: doDiv(); break; case 0: printf("종료합니다!\n"); break; default: printf("잘못된 선택입니다.\n"); } } int main() { int choice; do { showMenu(); scanf("%d", &choice); processMenu(choice); } while (choice != 0); return 0; }

연습 문제

1
리팩토링 이유
쉬움
main 함수가 100줄이 넘으면 어떤 문제가 생기나요? 2가지 이상 설명하세요.
정답 보기
① 읽기 어려워진다 ② 버그 위치를 찾기 힘들다 ③ 특정 부분만 수정하기 어렵다 ④ 코드 재사용이 불가능하다
2
do-while 이해
쉬움
메뉴에서 do { ... } while(choice != 0);을 쓰는 이유는?
정답 보기
do-while은 조건 검사 전에 한 번 반드시 실행됩니다. 메뉴는 최소 한 번은 보여줘야 하므로 do-while이 적합합니다.
3
새 메뉴 항목 추가
보통
위 프로그램에 "5. 나머지 연산"을 추가하세요. showMenu, processMenu, doMod 함수를 각각 수정/추가합니다.
힌트 보기
doMod() 함수 작성 → showMenu에 "5. 나머지" 추가 → processMenu의 switch에 case 5: doMod(); 추가
4
잘못된 입력 반복 처리
어려움
1~4나 0 이외의 숫자를 입력하면 "잘못된 선택입니다. 다시 입력하세요." 를 출력하고 메뉴를 다시 보여주도록 수정하세요.
힌트 보기
processMenu에서 default 처리 후 main의 do-while 루프가 메뉴를 자동으로 다시 보여줍니다. 별도 로직 없이 default 메시지만 바꾸면 됩니다.
핵심 정리

핵심 정리

  • 리팩토링: 동작은 유지하면서 코드 구조 개선
  • showMenu() — 출력만, processMenu() — 처리만 (단일 책임)
  • do { } while(choice != 0) — 최소 한 번 실행 보장
  • 함수 분리 후 새 기능 추가가 훨씬 쉬워짐

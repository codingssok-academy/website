비트 필드 — 구조체 패딩과 정렬

비트 단위로 멤버 크기를 지정하는 비트 필드와, 컴파일러가 자동으로 추가하는 패딩(padding)을 이해해봅시다.

이 유닛에서 배우는 것

  • 비트 필드(bit field) 문법을 작성할 수 있습니다.
  • 비트 필드가 메모리를 절약하는 방식을 이해합니다.
  • 구조체 패딩(padding)이 왜 생기는지 설명할 수 있습니다.
  • 멤버 순서를 조정해 구조체 크기를 줄일 수 있습니다.
  • #pragma pack을 이해합니다.

비트 필드(Bit Field)

구조체 멤버 뒤에 : 비트수를 붙이면 해당 멤버가 몇 비트를 차지할지 지정할 수 있습니다. 1~0 같은 플래그를 메모리 효율적으로 저장할 때 유용합니다.

struct Flags { unsigned int isAdmin : 1; // 1비트 (0 or 1) unsigned int isLoggedIn: 1; // 1비트 unsigned int level : 4; // 4비트 (0~15) unsigned int unused : 2; // 2비트 (패딩용) }; // 총 8비트 = 1 byte (int 단위로 정렬되므로 실제 4 bytes) struct Flags f; f.isAdmin = 1; f.isLoggedIn = 1; f.level = 7; // 4비트 최대 15 printf("admin=%d, login=%d, level=%d\n", f.isAdmin, f.isLoggedIn, f.level);

구조체 패딩(Padding)

컴파일러는 CPU가 데이터를 빠르게 읽도록 멤버를 정렬(alignment) 합니다. 이 과정에서 사용하지 않는 빈 공간(패딩)이 생깁니다.

패딩 줄이기 — 멤버 순서 최적화

// 비효율적 배치 (패딩 많음) struct Bad { char a; // 1 + 패딩 3 int b; // 4 char c; // 1 + 패딩 3 }; // sizeof = 12 // 효율적 배치 (패딩 최소화) struct Good { int b; // 4 char a; // 1 char c; // 1 + 패딩 2 }; // sizeof = 8 printf("%zu %zu\n", sizeof(struct Bad), sizeof(struct Good)); // 12 8

#pragma pack — 패딩 제거

#pragma pack(1) // 1 byte 정렬 (패딩 없음) struct Packed { char a; int b; char c; }; // sizeof = 6 (패딩 없음) #pragma pack() // 정렬 복원 printf("%zu\n", sizeof(struct Packed)); // 6
핵심 정리

핵심 정리

  • 비트 필드: unsigned int 이름 : 비트수; — 해당 비트 수만큼 사용
  • 패딩: 컴파일러가 정렬을 위해 자동 추가하는 빈 공간
  • 패딩 최소화: 큰 타입 → 작은 타입 순서로 배치
  • #pragma pack(1): 패딩 완전 제거 (성능 영향 주의)
